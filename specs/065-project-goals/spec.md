## User Scenarios & Testing

### User Story 1 - Projects, goals and Home (Priority: P1)

A Project is the processing unit. It names its subjects (Targets), the rigs whose sessions it suggests, and goals per subject and channel. It holds the sessions the user adds, grouped by rig and framing, and one input folder, its View. Matching sessions are suggested and never added automatically. Home is a dashboard that shows every Project's progress and one Next action. The user wraps the Project up in one ordered flow: clean up, trash what is no longer needed, archive, then close the Project, which locks it for good; Duplicate continues it (D-W1, D-W26, D-W39, D-W80, D-W94 to D-W97).

**Why this priority**: This feature owns the workflow steps listed below without imposing unrelated product features.

**Independent Test**: Exercise the acceptance scenarios through the running product with isolated inputs. Existing baseline code does not prove the redesigned behavior.

### Edge Cases

The [root contract](../063-clean-rebuild-contract/spec.md) governs file custody, uncertainty, exact membership, failed writes, and independent lifecycle decisions. Each acceptance scenario tests observable outcomes; no mock acknowledgment counts as terminal success.

- A session whose OBJECT header names a subject but whose Target is not confirmed is not suggested. Home lists it under "needs a Target". (D-W33, D-W35)
- A session with a confirmed subject Target on a rig the Project does not list is not suggested. Adding that rig to the Project suggests it without changing the Project's sessions. (D-W37, D-W96)
- Removing a rig or a subject changes only the suggestions. The Project's sessions stay until the user removes them, and a removal is a pending change once the View exists. A subject's goals stay hidden in the Project while it is removed and are restored when the subject is added back (owner's answer, 2026-10-19, astro-plan-rzbzu.1). (D-W94, D-W100)
- A session the Project holds stays when its own Target or rig association changes, and it still counts "in project" and "captured". Its row shows the new association. (D-W94, D-W96)
- Adding or removing sessions changes no file until Apply and never changes a library frame or quality decision. (D-W94, D-W100)
- Geometry never decides which sessions are suggested. It orders suggestions and forms framing groups; a session without pointing evidence is flagged for the user to place, never read as zero distance. (D-W33, D-W95)
- A content-identical frame in two sessions of one Project counts once in project.
- A drifted frame leaves "in project" until its reviewed bytes return or it is reconfirmed. Offline or unreadable frames keep their labelled last-observed contribution (root D19).
- A Trashed frame counts in neither "in project" nor "captured" for any Project. A frame trashed while a Closed or Archived Project held it still shows, marked "Trashed", in that Project. (D-W43, D-W52, D-W97)
- The interface calls the Project's input folder the View. (D-W94)

## Requirements

### Functional Requirements

- **PRJ-FR-01**: New Project takes a name, optional notes, one or more subjects, one or more rigs, and goals. Goals can be added directly, with no goal template, or copied from a template chosen in a compact selector (PRJ-FR-12). A subject is a Target, with no limit on how far apart subjects are; there is no mosaic subject, because a mosaic is a Project with panel groups (PRJ-FR-29). Opening New Project from a Target prefills that Target. A Project is required for processing, and never required for library inspection, Import or the Planner. (D-W1, D-W9, D-W16, D-W90, D-W95)
- **PRJ-FR-02**: A Project lists the rigs whose sessions it suggests (provisional). Adding or removing a rig or a subject changes only the suggestions; the Project's sessions stay until the user removes them. A removed subject's goals stay hidden in the Project, and adding the subject back restores them (owner's answer, 2026-10-19, astro-plan-rzbzu.1). Re-pointing a subject at a Target with hidden goals restores them, and the subject's goals they replace are hidden under its old Target. A subject removed with no goals comes back with the template's goals, and a hidden panel goal whose group is gone is dropped (D-W134, D-W135, D-W136; owner's answer, 2026-10-20). Adding a session whose rig or Target the Project lacks adds them to the Project, and a visible note names them before saving. The Targets rig selector can choose "this Project's rigs". (D-W37, D-W59, D-W94, D-W96)
- **PRJ-FR-03**: Goals are set per subject and channel, and per panel group in a mosaic. Each goal measures one unit, time or frames, chosen for that goal. A goal may carry an optional quality bar, "count only frames with FWHM ≤ x″": frames over the bar do not count and show as "+N h below bar", and a frame without the measurement the bar needs reads unknown and does not count toward that goal. In a mosaic Project, the subject completes when every panel group meets its goals, and its progress shows the weakest panel. Channel balance is not a goal: the Project page shows each subject's ratio of counted time per channel next to the ratio its goals imply. Exposure preference, equipment goals, spread over nights and Moon limits are not goal kinds. Goals stay editable while the Project is open, and a goal change needs no Apply. (D-W9, D-W29, D-W90, D-W95, D-W96)
- **PRJ-FR-04**: Every integration and frame-count goal shows two labelled numbers. "in project" counts the frames of the Project's own sessions, each content-identical frame once. It leaves out the Project's exclusions, Trashed frames and frames the goal's quality bar does not admit. "captured" adds the frames of every matching suggestion, settled or not (provisional), each content-identical frame once and Trashed frames aside, so "in project" never exceeds "captured". Each Project counts its own sessions, so a session that two Projects hold counts in each, while Target and library totals count it once. Goal met and Home's Next action use "in project" only. An unmet goal never blocks Apply, and met goals never close the Project. (D-W36, D-W43, D-W79, D-W96)
- **PRJ-FR-05**: Creating or editing a Project writes only catalog Project records (subjects, rigs, goals, notes, sessions, groups and settings) and, once its View exists, pending changes. No file changes until Apply, and no quality state changes. (D-W94, D-W100)
- **PRJ-FR-06**: A Project has no single capture site; its sessions keep their own capture sites.
- **PRJ-FR-07**: The Project page shows its subjects, rigs, goals with progress and warnings, and planning for its own subjects with "Open in Planner", above the steps Sessions, Calibrate, View, Output and Wrap up (provisional step list, from the approved F4 prototype plan). Sessions shows the Project's groups with their sessions, its suggestions and its pending changes (PRJ-FR-27, VSEL-FR-12). Calibrate is the read-only check with the calibration diagram (CAL-FR-09). View holds the application, the input mode, Apply and Open in {app} (VSEL-FR-16, PREP-FR-04). Output lists the Results (RES-FR-01). While the Project is open, Sessions, View and Output stay editable, and Calibrate stays read-only. The Project menu offers Edit… and Duplicate…. (D-W7, D-W16, D-W94, D-W96, D-W97, D-W100, D-W101)
- **PRJ-FR-08**: A session joins a Project only when the user adds it, from the Project's suggestions, from a session row's Add to Project, or with Add sessions… on the Sessions step (VSEL-FR-03). Only a Ready session with settled calibration can be added (PRJ-FR-09). A Project adds and removes whole sessions, never single frames of a session (D-W107). Once the View exists, removing a session is a pending change. Several Projects may hold the same session. Project edits and goal changes never rewrite source files or library quality decisions. (D-W94, D-W96, D-W105, D-W107)
- **PRJ-FR-09**: A Project suggests every Ready session (LIB-FR-20) it doesn't hold whose confirmed Target is one of its subjects and whose rig is on its rig list (provisional). A Target associated by agreeing pointing evidence counts as confirmed. Suggestions show on the Project's Sessions step and on Home and are never added automatically. A suggested session whose calibration isn't settled reads "Choose its flats first" (or its darks or bias, provisional copy) and can't be added until it is settled (LIB-FR-23). A session that still needs review is not suggested, an OBJECT label alone confirms no Target, and Trashed sessions and frames are never suggested. (D-W33, D-W37, D-W43, D-W78, D-W96, D-W105; owner's answer, 2026-10-19, astro-plan-rzbzu.1)
- **PRJ-FR-10**: Withdrawn (D-W94). There are no processing runs to start; PRJ-FR-31 covers grouping a Project's sessions by rig and framing.
- **PRJ-FR-11**: Exposure mismatch is an automatic warning per subject and channel, computed from the Project's sessions. It is not a goal and never blocks Apply. A session can join only with settled calibration, so a Project shows no missing-calibration warning; a suggestion that needs calibration says so (PRJ-FR-09). The product shows no mixed-equipment warning. (D-W29, D-W105)
- **PRJ-FR-12**: Settings > Goal templates lists the built-in templates plus user templates the user can create, edit and delete. Each template defines its channels and goal values. The built-in templates and their values are:
  - HOO: Ha 10h and OIII 10h.
  - SHO: Ha, OIII and SII 10h each.
  - LRGB: L 6h, and R, G and B 2h each.
  - OSC broadband: 10h.
  - OSC dual-band: 15h.

  Applying a template to a Project copies its values into the Project, where they stand alone and stay editable. A template also carries the goal conditions of PRJ-FR-23 and PRJ-FR-24. Templates are never filtered by rig. (D-W30, D-W47, D-W90)
- **PRJ-FR-13**: Withdrawn (D-W79). Project-scoped rejects are removed; "in project" leaves out only the Project's exclusions, Trashed frames and frames outside a goal's quality bar (PRJ-FR-04).
- **PRJ-FR-14**: Only the user closes a Project, and only through its **Wrap up**, a step flow (FR-024) that replaces the Done / Archive sheet. Provisional: Wrap up opens once no change is pending and no PlateVault operation runs on the Project; until then it reads "Apply or discard N changes first ▸" (provisional copy), leading to the View step. Its steps run in a fixed order: Clean up → Trash → Archive. A later step stays read-only until the earlier ones are Finished or Skipped, and an earlier step can be reopened until the Project is closed. Each step is a table of what it offers, with the recommended rows preselected, and each row expands to the exact files it moves; Archive rows show each file's from and to paths. Proceeding with nothing selected records a step Skipped, so every step, Archive included, is optional. A step with nothing left to offer says so, and Proceed records it Finished. A row that cannot be selected says why in its status, such as "Linked by {project} ▸", "Read-only", "Offline" or "Used by {project} ▸". Clean up offers removing the View, with its Copies ticked and its Symlinks unticked. Provisional: Clean up also lists whatever `View (previous)/` still holds, including files PlateVault didn't place, each unticked (STO-FR-01). Trash holds the three groups of PRJ-FR-15. Archive lists the Project's sessions it moves (STO-FR-13). It keeps every session that another open Project holds. A Closed or Archived Project doesn't keep a session, and being another Project's suggestion does not count. PV-STO executes each step under the root custody and archive rules. Archive's Proceed is **Close project…**: its confirmation lists the archive moves and the outcome of the first two steps. The archive transfer runs in the background, and the Project reads Closing until it succeeds, then Archived, or Closed when nothing was archived. Close keeps `Output/` (RES-FR-06) and, provisionally, records the calibration each group and night used (PRJ-FR-25). (D-W26, D-W46, D-W77, D-W80, D-W97)
- **PRJ-FR-15**: Wrap up's Trash step offers trashing a Project's capture frames, `Processing/` files and duplicate copies. Outside a Project, the library clean-ups of STO-FR-18 offer Unusable frames and duplicate copies (D-W156). PV-PRJ owns what each Wrap up offer covers and refuses; PV-STO executes the approved moves (STO-FR-14 to STO-FR-16). The step has three groups. It offers "Move N rejected frames to Trash (size)", covering the Project's frames whose applicable library quality is Unusable. ChangedContent frames (LIB-FR-09) and Trashed frames are never included. It lists each refused frame with its reason: in the View of another open Project. A Closed or Archived Project's kept View doesn't block a frame, the same rule as Archive (STO-FR-13). It also offers "Move N processing files to Trash (size)" (provisional copy), covering the files in the Project's `Processing/` folder, which replace the processing intermediates of D-W70. `Output/` and adopted masters are kept, and a generated master the user hasn't decided on is named so it can be adopted first (CAL-FR-06). An adopted master's generated source counts in that N and moves under the same approval, listed as a verified duplicate that names the kept library copy. The step also offers "Move N duplicate copies to Trash (size)", covering the byte-identical (SHA-256) extra physical copies of the Project's frames: its sessions' frames and the calibration frames those sessions use. It keeps one copy of each frame and names it. The kept copy is the one in a Captures or Calibration location, the earliest-registered such location when there are several, and otherwise the copy in the earliest-registered location. When copies tie because they sit in the same location, the copy PlateVault catalogued first is preselected as the kept copy, and nothing is removed without review. It refuses an extra copy that the View of another open Project links or copies, and lists each refused copy with its reason. A Closed or Archived Project's kept View doesn't block a copy. All three groups follow the D-W43 trash rules: approved items go to the OS Trash only under the PV-STO custody rules, with no permanent delete. Every refusal is listed with its reason, including each custody refusal of STO-FR-15. (D-W43, D-W70, D-W74, D-W79, D-W80, D-W97, D-W116, D-W156)
- **PRJ-FR-16**: A Trashed record stays in the catalog for traceability. It is hidden from suggestions, the Project's sessions, goals, totals, the Project page and Home. Only the Sessions "Trashed" filter (PV-LIB) shows it, and so does a Closed or Archived Project that held the frame when it was trashed, marked "Trashed". Put back from the OS Trash followed by a rescan restores the record as Unusable. (D-W43, D-W52, D-W97)
- **PRJ-FR-17**: Home is one page of what needs the user, what is running and when to capture next, built from the shared components, with no tabs and no header buttons. From 1280 px wide it has two columns: Pending ingestions, Pending work and Open work on the left, and Status, Tonight and the calendar on the right. Narrower, it is one column in that order. The order is fixed. Each section shows at most 5 rows, then "All N ›", which opens the owning page filtered to those items, and each row opens the page that owns it. The sections are:
  1. Pending ingestions, per Captures location: new files since its last scan ("142 new files · Import"), a location never scanned or whose last scan did not finish, and stopped or failed imports with Retry. A running import changes its own row ("Importing 142 files · 40%").
  2. Pending work: sessions that need a Target, review or calibration (LIB-FR-17), sessions not in a Project, and sessions an open Project suggests.
  3. Open work: open Projects, plus calibration processes. Each row shows where it stands and its next step (PRJ-FR-18). Rows sort by deadline or season window and carry "N nights left" (PRJ-FR-23).
  4. Status: locations, each online or offline with its free space and a low-space flag, and background jobs; imports show in Pending ingestions instead.
  5. Tonight: the unfinished goals graded for tonight at the default site (PLAN-FR-11). Home names the site; the user changes it on Targets.
  6. Calendar: five weeks starting this week (PLAN-FR-12).

  Problems show on the row they affect, and Home has no alerts list. A Project waiting on the user, or drift, shows on its Open work row. An offline or unreadable location shows on its Status row, and a failed import in Pending ingestions. An old master raises no problem anywhere; its "Old" badge shows only in the calibration library (CAL-FR-15). Drift on anything Home does not show appears on that item's own row (FR-032), and Home does not list duplicate candidates. Home leaves out recent Projects, the activity log, charts and statistics, result thumbnails, the setup checklist and weather. One-click buttons appear only for actions that need no further input and can be undone, and each shows an Undo notice. (D-W27, D-W35, D-W89, D-W92, D-W103, D-W105)
- **PRJ-FR-18**: A Project's Next action is the first rule that applies:
  1. Sessions that match its subjects and rigs still need review: "N sessions need review", which opens Sessions filtered to Needs review (LIB-FR-17).
  2. The Project waits on the user: a suggested session needs calibration, an Apply was refused or failed, or `View (previous)/` holds files to review. The Project opens at that step (provisional).
  3. A goal is unmet in project and tonight has an observing window for that subject (PLAN-FR-11): "Plan tonight".
  4. Otherwise: "Apply N changes" when changes are pending, "Open in {app}" once the View exists, or "Add sessions" before that (provisional copy). (D-W27, D-W35, D-W48, D-W96, D-W100)
- **PRJ-FR-19**: Home has no summary line above its sections; sessions that need a Target or are not in any Project are rows of Pending work (PRJ-FR-17). A session needs a Target when it has no confirmed Target, including unresolved and Needs review associations; agreeing pointing evidence confirms its Target. A session is not in any Project when it has a confirmed Target and no Project holds it. Its row offers Create Project, or Add to Project, which adds the session and, when the Project lacks them, its Target as a subject and its rig. A visible note names the added rig before saving (LIB-FR-17). A row for a session an open Project suggests opens that Project's suggestions. (D-W35, D-W37, D-W39, D-W59, D-W89, D-W96; owner's answer, 2026-10-19, astro-plan-rzbzu.1)
- **PRJ-FR-20**: Withdrawn (D-W94, D-W97). There are no run stages, no Project Trash list and no Reopen; PRJ-FR-32 covers the next step and pending count in Open work and the Projects list.
- **PRJ-FR-21**: The interface calls the Project's input folder the View, labels goal progress "in project" and "captured", and never shows "in project" above "captured". (D-W36, D-W66, D-W94)
- **PRJ-FR-22**: Home's empty sections read:
  - Pending ingestions: "Everything is imported."; on first run, "Add a Captures location to find new captures." with Add location.
  - Pending work: "Nothing to sort or review."; on first run, "Import captures to start sorting them." with Import….
  - Open work: "No Projects in progress." with New Project….
  - Tonight, until Home's planning criteria are saved: no grades and no next good night (PLAN-FR-11).
  - Tonight, when no goal suits the night: "No goals suit tonight. Next good night: {date}."; on first run, "Add a site to see tonight's darkness and Moon." with Add site.
  - Tonight, when there are no goals at all: "No unfinished goals." with Add a Goal (the owner's exact label, astro-plan-b66vy), which opens a menu of open Projects and then that Project's add-goal dialog.
  - Status, background jobs: "Nothing running." (D-W89, D-W170)
- **PRJ-FR-23**: Each subject may carry an optional deadline: a "Finish by" date or a season window, pre-filled from the Target's visibility. A Target visible all year has no season window. Progress then shows the nights left, and Home's Open work and Tonight rank the subject higher as the date nears. Conditions are set in Settings > Goal templates and edited per subject. (D-W89, D-W90)
- **PRJ-FR-24**: In a mosaic, panel balance keeps each channel's counted integration of every panel group within ±N % of the panels' mean, counting Usable frames inside the quality bar, or frames when the goal counts frames. N defaults to 10 and the user can change it. A panel outside the band shows a warning; balance never blocks completion. (D-W90, D-W95)
- **PRJ-FR-25**: A Closed or Archived Project is locked for good: no edits, no Apply, and Library or calibration changes never touch it. Its header shows Closed or Archived, and its menu offers only Duplicate…; Edit… is disabled and says "Project closed · Duplicate ▸" (provisional copy). Open in {app} stays available while its View exists. The Wrap up tab is a read-only record of each step's outcome. Its goals are read-only and freeze at Close. To continue a finished target, the user duplicates the Project (PRJ-FR-30). Provisional: there is no Reopen, and Close records a snapshot of the calibration each group and night used, so a later reassignment never changes a Closed or Archived Project. When Archive moves originals that its kept View links to, Archive repoints those links and records it, and nothing else in the Project changes (STO-FR-06). Frame review is not reachable from a Project, and library marks stay editable from Sessions (D-W78); they never change a Closed or Archived Project's sessions or snapshot. Renaming one of its sessions in the Library (LIB-FR-28) changes only the session, and the Project shows the new name (D-W130; owner's answer, 2026-10-20). (D-W76, D-W78, D-W80, D-W90, D-W97, D-W111, D-W112)
- **PRJ-FR-26**: Withdrawn (D-W94). With processing runs gone, removing a subject or a rig changes only the suggestions (PRJ-FR-02), and a subject's Target can change while the Project is open. F9 and Q19 are withdrawn.
- **PRJ-FR-27**: The Sessions step shows the Project's groups with their sessions. The user can create a group, split one, rename one and move sessions between groups. Creating a group asks for its name, prefilled with a default: the rig's name when the Project has one rig, "<Rig> · Framing 2" for a second framing on the same rig, "Panel N" for a mosaic panel (from the NINA or capture name when there is one, otherwise numbered) and "<Rig> · 2" for a split. Every group can be renamed, and a rename changes its folder on the next Apply. Spaces become hyphens only in the View keyword folders (`GROUP_`, `PANEL_`, `NIGHT_`), never in the Project folder (D-W114; owner's answer, 2026-10-19, astro-plan-rzbzu.1). Only ASCII letters, digits, space and `- ( ) : .` are kept (D-W99; fact check against PJSR, 2026-10-19, astro-plan-rzbzu.1). Once the View exists, every group change is a pending change (VSEL-FR-12). (D-W95, D-W100)
- **PRJ-FR-28**: A group's folder carries a keyword token: GROUP by default, and PANEL for a group marked as a mosaic panel. Both keyword names are set in Settings > Naming, one row each (STO-IMP-FR-09), and can be changed per Project under the same naming rule, and a panel group carries only the PANEL token. The group folder level appears only when the Project has several groups (PREP-FR-16), so a one-group Project has none, even when its group is a mosaic panel (D-W114). When a second group appears, the next Apply changes the layout, and its sheet says to re-add View in the tool (provisional copy, VSEL-FR-14). (D-W95, D-W146)
- **PRJ-FR-29**: Mosaic is not a mode chosen up front. Marking a group as a mosaic panel makes the Project a mosaic: its panel groups get `PANEL_` folders and "Panel N" names, each panel has its own progress and goals (PRJ-FR-03, PRJ-FR-24), the Project page shows a panel map from the groups' framings, and `Output/Panels/` holds each panel's result, with the finished mosaic in `Output/` (RES-FR-08). Two framings that overlap by 5 % to 40 % are offered as panels of one mosaic, a default adjustable in Settings (D-W114). PlateVault makes no processing folders for the panels; the user assembles the mosaic in their tool. (D-W95, D-W98)
- **PRJ-FR-30**: Duplicate… copies everything the user chooses from the Project: its sessions, groups and overrides, goals, notes and settings. It copies no files, and its sessions use their current calibration pins, not the original's Close snapshot. The new Project has no "Duplicated from" note and no link to the original. Duplicate is offered on open and Closed or Archived Projects, and on a Closed or Archived Project it is the way to continue. The duplicate is open and builds its own View with its first Apply. (D-W93, D-W96, D-W97, D-W112)
- **PRJ-FR-31**: PlateVault groups a Project's sessions by rig and framing (pointing and rotation). Each session has one framing, because intake splits sessions by framing (LIB-FR-04), so a group holds whole sessions and PlateVault never divides a session's frames between groups. Defaults, adjustable in Settings: two sessions share a framing when coverage is at least 90 %, their centre separation is at most 5′ (owner's answer, 2026-10-20) and their rotation within 5°. Coverage uses the rig's field of view, from its effective focal length: the telescope's focal length times its reducer's factor (PLAN-EQ-FR-05, D-W155). The tolerance allows for a manual rotator across nights. Rotation comes from ROTATANG, a meridian flip doesn't change it, and when only the sky angle is known, 180° counts as the same framing. A new rig version starts a new group only when the optics change: focal length, reducer or camera (PLAN-EQ-FR-07). Intake uses the same centre and rotation margins to split sessions, unless import review sets them for that import (D-W107; owner's answer, 2026-10-20). A session without pointing evidence joins its rig's group flagged "Framing unknown" until the user moves it (provisional). (D-W95, D-W107, D-W114, D-W155)
- **PRJ-FR-32**: A Project is open until its Wrap up closes it (PRJ-FR-14). Open work and the Projects list show each open Project's next step (PRJ-FR-18) and how many changes are pending. There is no stage rail, no run list and no Project Trash list. (D-W7, D-W80, D-W94, D-W97)

### Key Entities

Use the [root vocabulary](../063-clean-rebuild-contract/spec.md#key-entities). Feature-specific evidence and decisions retain their input identity, scope, and revision.

- **Subject**: A Target that a Project names. (D-W9, D-W94)
- **Project rig list**: The rigs whose sessions a Project suggests (provisional). (D-W37, D-W96)
- **Group**: A set of the Project's sessions with one rig and framing, or one mosaic panel, with a name and a GROUP or PANEL keyword token. (D-W95)
- **Goal**: An integration, frame-count or quality-bar target for one subject and channel, or one panel group. (D-W29, D-W95)
- **Goal template**: A built-in or user set of channels and values that is copied into a Project when applied. (D-W30)
- **Suggestion**: A derived session: it is Ready, its confirmed Target is a subject, its rig is on the rig list and the Project doesn't hold it. It can be added only once its calibration is settled. (D-W96, D-W105)
- **Project session**: A session the user added to the Project. It counts "in project" and stays until the user removes it. (D-W94, D-W96)
- **Project state**: Open, Closed or Archived. Wrap up's Close project leaves the Project Archived when its Archive step moved sessions, and Closed otherwise. Closed and Archived are locked for good, with no Reopen (provisional). (D-W26, D-W80, D-W97)
