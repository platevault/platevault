# Project goals research

## Decision

Store Projects as Tier 1 records in the clean library catalog, `crates/persistence/library`, through its single serialized writer. Compute progress in one reader snapshot with the same logical-capture and D19 rules as Target coverage. Evaluate checklist kinds in a pure `platevault_core::projects` module. The isolated rebuilt shell exposes `project_*` commands. The plan reuses no legacy project table, command or orchestration.

## Source evidence

Read at `08491ea91ed1a8f89fe397eab65d7e6cff51e190`, the reviewed 064 backend. No runtime behavior is claimed from reading.

- Catalog durability: `Catalog::open` opens one writer with WAL, FULL synchronous, foreign keys and macOS fullfsync, then a read-only pool. `write_txn!` runs `BEGIN IMMEDIATE` and commits (`crates/persistence/library/src/lib.rs:52-64`, `:324-347`).
- Schema versioning: `catalog_meta.schema_version` is 6. `install_schema` refuses any other recorded version before DDL and has no migration chain (`lib.rs:45-46`, `:2066-2102`; `schema.sql:8-16`).
- Coverage: `Catalog::target_coverage` reads the current members of counted sessions and groups logical captures with `CaptureView`. It counts one primary copy per capture, skips Retired copies and labels the oldest `lastVerifiedAt` (`lib.rs:1560-1635`). `contributions_for` sums light exposure by applicable quality (`lib.rs:5616-5686`). The wire types are `TargetCoverage` and `CoverageContribution` (`crates/platevault-model/src/lib.rs:877-917`).
- Quality and CAS: `Asset::applicable_quality` and `logical_quality` derive ChangedContent, VerificationPending and conflicts (`model/src/lib.rs:553-612`). `check_expected_assets` refuses stale revisions, changed fingerprints and Retired copies (`lib.rs:4334-4366`). `check_expected_sessions` returns Conflict with lineage successors for a superseded session (`lib.rs:4882-4910`).
- Reference seam: the `AssetReferences` trait names VSEL, PRJ and RES as implementers. Retire review reads every registered source and reads it again on confirmation (`crates/platevault-core/src/library.rs:32-46`, `:194-241`). `ReferenceKind::Project` and `AssetReference` already exist (`model/src/lib.rs:962-985`).
- Targets and equipment: saved `targets` and `equipment` rows carry decision revisions (`schema.sql:216-256`). A seed Target becomes a catalog row only through `library_save_target` (`apps/desktop/src-tauri/src/commands/library.rs:274-294`). `TargetCandidate.coordinates` is optional and carries provenance (`model/src/lib.rs:813-831`).
- Capture-site evidence: `CaptureMetadata` holds `site_latitude_deg` and `site_longitude_deg` from SITELAT/SITELONG headers (`model/src/lib.rs:435-436`).
- IPC: handlers take `State<Arc<Library>>` and return `Result<T, ErrorResponse>` (`commands/library.rs:25-50`). The isolated shell registers its handlers with `generate_handler!` (`apps/desktop/src-tauri/src/library_shell.rs:68-98`). The dev bridge compiles only with `dev-tools`, binds IPv4 loopback and fails release compilation (`library_shell.rs:23-27`, `:164-190`). `scripts/check-dev-surface-absent.sh` guards release builds.
- SQL boundary: `scripts/check-db-boundary.sh` allows production sqlx calls only under `crates/persistence`.
- Legacy surface: `apps/desktop/src-tauri/src/commands/projects.rs` defines legacy `projects_*` commands over the old application state. The isolated shell does not register them.
- Frontend: the rebuilt commands have no TypeScript bindings or callers. Frontend acceptance stays a separate task, as in 064.

## Resolved ambiguities

Each entry records the decision, its basis and the alternative considered. Where the spec is silent, the default follows the root [decision register](../063-clean-rebuild-contract/decisions.md).

- **R1 Storage.** Project tables live in `crates/persistence/library/src/projects.sql`, appended to the catalog schema, with SQL in `src/projects.rs`. The schema version becomes 7. A version-6 catalog is refused like any other version; the autonomous objective permits resetting development catalogs. Basis: one serialized writer, one reader snapshot for progress joins and the existing private `CaptureView` helpers. Alternative: a separate persistence crate needs a second writer connection or public library internals.
- **R2 Target framing.** A Project names saved Target records. Each entry snapshots the Target's coordinates, provenance and decision revision when the user confirms framing. A later Target edit reads `framingChanged` until the user confirms the new revision. A seed Target is saved first through `library_save_target`, as association requires. Basis: D12 explicit coordinates; VSEL geometry must not move silently. Alternative: reading live Target coordinates would change Project framing without review.
- **R3 Framing presence.** Creation takes the prefilled Target. Every revision keeps at least one Target or panel. Basis: PRJ-FR-01 and the Target key entity, which lists its Projects.
- **R4 Equipment.** The Project records an ordered set of saved Equipment IDs for VSEL preselection; the set may be empty. Recording it changes no association, capture key or quality (D11). Basis: the root Project entity spans equipment.
- **R5 Session linkage.** Linking takes `ExpectedSession` values, so a stale or superseded session is refused with its successors. A link whose session a later correction supersedes stays recorded and reads NeedsReview with successor IDs. It contributes no progress until the user links successors. Basis: D12 explicit linkage and D15 traceability. Alternative: the 064 association rule inherits a confirmation when every successor asset shared it. That carry-over is not adopted, because the spec defines no automatic Project linkage.
- **R6 Panel coverage.** Each link may name one Project panel. Panel-coverage evidence lists the linked sessions assigned to each panel. Basis: D12 requires qualified D01 geometry for automatic panel coverage. VSEL owns that geometry, and J21 G2 leaves its overlap criterion open.
- **R7 Channel identity.** A checklist channel matches the effective FILTER text exactly. Frames with unknown FILTER appear in an unknown-channel row and count toward no channel goal. Spelling variants are fixed through reviewed catalog corrections (D15). Alternative: alias folding would invent channel identity.
- **R8 Arithmetic.** Progress sums each frame's effective exposure rounded to whole microseconds as integers. An integration item is met when Project-accepted microseconds reach the goal. Goals are whole seconds or whole frames. Frame counts count logical light captures (D16). Basis: floating sums of decimal exposures can miss an exact goal boundary.
- **R9 Project rejection.** Rejection is an append-only decision per Project and asset, set or withdrawn explicitly like `library_set_quality`. It takes `ExpectedAsset` values and performs no rehash, because it only removes frames from the met basis. A rejection of any copy applies to the logical capture. It stays independent of linkage, and Retired copies take no new decision. VSEL calls the same operation from Project-owned Views (VSEL-FR-11). Basis: D10 separate records; PRJ-AC-08 and J22/S13 reject a library-Unreviewed frame.
- **R10 Evidence kinds.** Exposure-preference and equipment items report each linked session as matches, differs or unknown. They have no met state and no hour total. Basis: D10 and PRJ-FR-04.
- **R11 Missing calibration.** Until calibration matching from 068 exists, this item reads unknown with reason `calibration_matching_unavailable`. It never infers compatibility. Basis: D13 makes CAL the matching owner. The 068 plan supplies the evidence through its own contract.
- **R12 Lifecycle.** The spec defines no Close, Complete or Delete Project action. A Project therefore has no lifecycle state, and progress cannot change one. Any future close action needs its own specification and runs only on an explicit user action (D10).
- **R13 Views and products.** VSEL (066) and RES (070) own those records. They add `views` and `acceptedProducts` to `project_detail` when their tables exist. PRJ-AC-05 View creation and the View/product parts of PRJ-AC-06 and PRJ-FR-07 are verified with those features. 065 proves that the checklist state never gates or changes Project context reads.
- **R14 Capture sites.** Each linked session lists its distinct observed site coordinates with frame counts, or unknown. The plan applies no clustering tolerance. PLAN (072) owns names of saved sites. The Project has no site field (PRJ-FR-06).
- **R15 Revisions.** Every Project mutation compares and increments one Project decision revision. A stale request returns Conflict with the current revision.
- **R16 Naming.** Commands use the `project_` prefix in `commands/project_goals.rs`, because legacy `commands/projects.rs` holds `projects_*` commands.
- **R17 Retire interplay.** `ProjectReferences` implements `AssetReferences` for linked-session members and rejected assets. Its revision is the Project revision, so a Project edit after review blocks retire confirmation until a new review.

## Qualification

Generated FITS/XISF fixtures must cover Ha and OIII lights at 300 s, two capture sites, another camera and an offline location. They also need a regroup correction, logical-capture copies, verification-pending and drifted decisions, and SQLITE_FULL. Every scenario compares source hashes before and after. Real development-MCP evidence remains an acceptance gate. No legacy test result proves the rebuild.
