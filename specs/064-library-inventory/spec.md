## User Scenarios & Testing

### User Story 1 - Library: locations, indexing, sessions, Target/equipment evidence (Priority: P1)

Register locations, including OS-mounted network volumes, and index them in place. Form metadata-homogeneous sessions, show association evidence and Target coverage, and keep offline and partial-scan state accurate. Index what Import lands without an Inbox. Match flats, darks and bias to each light session at ingestion and pin them on the session, and hold a session whose calibration isn't settled in "Needs calibration". Point Sessions at sessions that need a Target, review or calibration, or belong to no Project. Keep Trashed frames out of every list and total except the Sessions "Trashed" filter.

**Why this priority**: This feature owns the workflow steps listed below without imposing unrelated product features.

**Independent Test**: Exercise the acceptance scenarios through the running product with isolated inputs. Existing baseline code does not prove the redesigned behavior.

## Requirements

### Functional Requirements

- **LIB-FR-01**: Onboarding Locations step: at least one Captures location is required. Calibration and Results are optional, and 'Set up later' is available. No workspace root is assumed. Each role supports multiple folders. Display names are editable. Each row shows path, role, volume kind (local, removable or network), access state, and online state. (D-W12)
- **LIB-FR-02**: Registering a location, including Import's "Add existing library folder", records only access and indexing intent and indexes the folder in place. It does not copy, rename, move, or delete anything. (D-W11)
- **LIB-FR-03**: Indexing shows progress: files discovered, metadata read, unsupported, unreadable, and completed scope. Results appear progressively, and sessions already read can be browsed during indexing. Totals name the locations they cover and mark scope as provisional while a scan runs.
- **LIB-FR-04**: Sessions are metadata-homogeneous (Ha and OIII are separate) and stay split by exposure time. A night supports multiple sessions. Intake splits a night's frames into separate sessions by framing, using the Project group margins of PRJ-FR-31: frames whose pointing is within 5 % of the field and whose rotation (ROTATANG) is within 5° stay one session, and a meridian flip doesn't split one. A larger shift starts a new session, named by default with a framing suffix, such as "NGC 7000 · Ha · 300 s · 14 Oct · framing 2". Each session therefore has one rotation. Frames with no pointing evidence stay in one session, because without pointing there is no framing split. The Sessions display supports grouping by night without changing session identity. OBJECT remains a label or filter, outside capture identity. (D-W107)
- **LIB-FR-05**: Target and equipment associations show the evidence used. Agreeing evidence permits association; unknown or conflicting evidence shows Needs review. A missing OBJECT with insufficient other evidence leaves the association unresolved. Confirm Target and Confirm equipment are available; Confirm equipment sets the session's rig, the optical train whose filter list PLAN-EQ-FR-01 defines, and the rig version it was captured with (LIB-FR-26). A session whose FILTER value matches no filter on its confirmed rig shows that filter as unknown in its Sessions row, with the "Add {value} to {rig}" prompt of PLAN-EQ-FR-04. Corrections change the catalog only, never source headers. (D-W31, D-W37, D-W104)
- **LIB-FR-06**: An incomplete or unreadable scan never marks unobserved files Missing. Readable siblings still reconcile.
- **LIB-FR-07**: An offline location keeps its last-observed metadata and quality decisions. Access denied names the failure and offers Choose folder again or Retry; other locations continue. Locate/remap to another verified location preserves asset identities using the same-asset proof in D11 of the root decision register.
- **LIB-FR-08**: Target search opens a Target page showing captured integration, library-wide usable integration, and Unreviewed integration by channel. Availability is a separate state. Offline contributions show their last observation and are not offered as available inputs. Usable totals come only from library-scope quality decisions. Content-identical copies in different locations count once as one logical capture that names every physical copy.
- **LIB-FR-09**: Persisted quality decisions are Unreviewed, Usable or Unusable; new frames start Unreviewed and measurement never sets Usable. Applicability is separate: ChangedContent preserves the previous decision when bytes differ or its historical review basis is absent. It exposes a distinct filter outside applicable Usable/Unreviewed totals until reconfirmed or the reviewed bytes return. Offline/unreadable inputs retain labelled last-observed quality, not an inferred content change.
- **LIB-FR-10**: PV-LIB owns local-first Sessions, the Target page (LIB-FR-08), Settings, shared main navigation and Activity operation outcomes. The Targets list belongs to PV-PLAN (PLAN-TGT-FR-01), and so does Settings > Equipment (PLAN-EQ-FR-01); Settings > Goal templates belongs to PV-PRJ, Settings > Naming to PV-STO and Settings > Applications to PV-PREP. The app opens on Home, the Projects dashboard (PV-PRJ), and main navigation gives Import (PV-STO) and Planning, the Targets list, their own entries. Core indexing and inspection need no account or network. (D-W7, D-W17, D-W39, D-W86, D-W87)
- **LIB-FR-11**: Failed catalog writes remain unsaved with Retry. Version checks detect external changes before overwriting app-written entries; stale edits are refused rather than merged silently. Only durable commits report saved success.
- **LIB-FR-12**: Catalog metadata corrections include Target, equipment and grouping values. Original observed evidence remains separate, and regrouping creates a traceable revision and never changes source headers. Provisional: regrouping never changes the sessions a Project holds (D15). Open: whether a correction that re-splits a session reaches the open Projects that hold it as a pending change (D-W100). (D-W94)
- **LIB-FR-13**: The target catalog supports local records, coordinate/alias search, explicit associations and provider-provenance enrichment through the shared resolver/matching contracts. Unavailable external services do not block core library use or fabricate associations.
- **LIB-FR-14**: Development builds include a functional Tauri MCP bridge for application control and verification. Production builds do not expose that development bridge; production MCP shipping is optional future work.
- **LIB-FR-15**: Retire location is an explicit, reviewed exit for a location the user does not expect to verify again, such as a deleted root or one moved without stable folder identity. Review names the location, root and availability and the assets, sessions and Projects that reference its copies, and states that retiring deletes, moves or modifies no file. Retirement is catalog-only: it reads and changes no file bytes, so D19 rehashing does not apply. Confirmation re-reads the location and is refused on a stale review or revision, when its availability differs from the reviewed availability, and while an operation affecting the location is Running or has unfinished items. A retired location is never reselected, rescanned or remapped. Its copies read Retired, never Missing; they are not offered as inputs, counted as available or included in captured, usable or Unreviewed integration or Project progress. Their last-observed metadata and decisions remain inspectable as history. The Projects that hold them keep their asset IDs and name retired copies unresolved, and Apply lists them among the unavailable originals (D02, D-W100). Retirement frees the root from the overlap check, so its folder can be registered again as a new location with new asset identities. No retired quality decision, Target or equipment association, or catalog correction transfers to them automatically; their sessions start from their own evidence. (D-W94)
- **LIB-FR-16**: Import (PV-STO) places files and the library indexes them as they land. Lights land in a Captures location and appear in Sessions as sessions, with no Inbox and no separate confirm step. Calibration frames (darks, flats, bias frames and masters) land in a Calibration location and appear in the Calibration library, never in Sessions, also when they arrive in the same import as lights. The catalog never gains a file that Import held back: an Unclassified frame until the user gives it a type, a file whose SHA-256 matches an indexed frame, or a file still being written. A skipped duplicate adds no copy and leaves the existing frame's identity, decisions and totals unchanged. Dark flats are ignored: never matched, suggested or assigned. (D-W24, D-W93, D-W105)
- **LIB-FR-17**: Sessions offers the filters "Needs a Target", "Needs review", "Needs calibration" and "Not in any Project". "Needs a Target" lists sessions with no confirmed Target, including unresolved and Needs review associations. "Needs review" lists sessions with a confirmed Target and rig whose review is not finished (LIB-FR-20); it is the review queue. "Needs calibration" lists every session whose calibration is not settled (LIB-FR-23), Ready or not, and every session whose pinned calibration file changed or went missing; it is the calibration queue. A just-imported session waits there while its review is still open, and Import never waits for it. "Not in any Project" lists sessions with a confirmed Target that no Project holds. It offers Create Project, prefilled with the session's Target as subject and its rig, and Add to Project, which adds the session and, when the Project lacks them, its Target as a subject and its rig. When it adds the rig, a visible note names it before saving. Both add only a session whose calibration is settled; otherwise they read "Choose its flats first" (or its darks or bias). The filters derive from current associations, quality decisions, calibration and Project sessions, and they add nothing to a Project by themselves. The counts of "Needs a Target", "Needs review", "Needs calibration" and "Not in any Project" are the ones Home's Pending work reports. Sessions also offers Archive… on the selected sessions: the reviewed transfer of STO-FR-06, under the rule of STO-FR-13. A session that an open Project holds can't be selected and reads "Used by {project} ▸". A session that only Closed Projects hold can be archived, and their kept Views are repointed, and being a Project's suggestion doesn't count. (D-W33, D-W35, D-W39, D-W59, D-W78, D-W96, D-W105, D-W113, D-W120)
- **LIB-FR-18**: A frame moved to the OS Trash from a Project's Wrap up (STO-FR-14) keeps its catalog record with the state Trashed. The record keeps its identity, SHA-256, last-observed metadata, quality history and the operation that trashed it. Every query and total excludes Trashed frames. That covers Project suggestions and sessions, frame review, Sessions, Targets, Home, overviews and goals. It also covers captured, usable and Unreviewed integration, location footprints and duplicate counts. A session whose frames are all Trashed leaves Sessions. The Sessions "Trashed" filter is the only list that shows them, with one exception: a frame trashed while a Closed Project held it still shows in that Project, marked "Trashed". No Project places a Trashed frame in its View. A rescan never reports a Trashed frame Missing. PlateVault offers no restore of its own. After the user chooses Put back in the OS Trash, a rescan that finds the file at its recorded path with a matching SHA-256 returns it as Unusable. The Trashed episode stays as history. Different bytes at that path follow the ChangedContent rule in LIB-FR-09. (D-W43, D-W52, D-W97)
- **LIB-FR-19**: A location may sit on a network share that the OS has already mounted. PlateVault does not mount shares and accepts no SMB or URL address. A location on a network volume is flagged as one in its row. Hashing on a network volume shows progress and is resumable: an interruption or unmount keeps completed hashes, and hashing resumes with the remaining files once the share is mounted again. An unmounted network location reads Offline under LIB-FR-07, never Missing or deleted. (D-W12)
- **LIB-FR-20**: Each session has an intake flow, Target → Rig → Review, under the root step flow (FR-024). Target confirms the session's Target, Rig confirms its rig, and Review is frame review over the session's frames (PIX-FR-18). Review's Proceed is **Finish review**, gated on no Unreviewed frame being left. Until Finish review the session reads Needs Target, Needs rig or Needs review, and afterwards **Ready**. Only a Ready session is suggested to a Project or can be added to one (PRJ-FR-09). Finish review opens the next session in "Needs review", and Import ends by opening the first one. Reopening review on a Ready session is always allowed. The marks it changes reach the open Projects that hold the session as pending changes labelled with their source, and never touch a Closed Project (VSEL-FR-12). Open: a frame set back to Unreviewed in a reopened review means the session is not Ready. What the open Projects that hold it show, and whether the change reaches them as a pending change, is not decided (D-W100). (D-W78, D-W97, D-W100)
- **LIB-FR-21**: Settings also holds these sections, which PV-LIB owns. Appearance sets the mode (Dark, Light or Follow system) and then the theme. The app has one density, with no density setting. Locations lists the registered locations (LIB-FR-01) as a table with each location's indexed state, frame count, footprint (the bytes PlateVault catalogues there) and the volume's used and free space. Help lists the keyboard shortcuts, tips and a guide, and replays the orientation walk (LIB-FR-27). About shows the installed app's version and data location, and nothing else. (D-W86, D-W117)
- **LIB-FR-22**: Sessions also offers the filter **Duplicates**. It lists every session with at least one live frame whose SHA-256 is held by more than one physical copy in registered locations. Trashed frames (LIB-FR-18), copies on unregistered volumes and frames whose digest is not yet known never count. Each listed session shows "{n} copies · {size}" and opens the Duplicates review. Wherever a session row appears (Sessions, a Target page, a Project's sessions and suggestions), it carries the same badge. Project rows carry none, because copies count once in their totals (LIB-FR-08), and there is no alert list (FR-032). Showing a duplicate never authorizes removing it (D16). (D-W92)
- **LIB-FR-23**: Flats, darks and bias are matched to each light session at ingestion under the rules of CAL-FR-19 to CAL-FR-23 and pinned on the session, and every Project looks up its sessions' calibration. A session's calibration is settled when each kind (darks, flats and bias) is either pinned or explicitly set to No darks, No flats or No bias. The No choice needs no reason, and a suggestion counts only once the user confirms it. A session's details show each kind with its state, pinned, suggested, No… or not found, and offer Reassign… per kind. When a pinned file changes or goes missing, the pin stays, the session shows the file as changed or missing with Reassign… and waits in "Needs calibration" (LIB-FR-17) until the pin is reassigned or the file's recorded bytes return; nothing switches to another file by itself. Provisional (lead default, to confirm with the owner): while it waits there the session is not settled, so no Project can newly add it, and the Projects that already hold it keep it. (D-W101, D-W105, D-W113)
- **LIB-FR-24**: Import never waits for calibration. Its review shows each new light session as intake split it (LIB-FR-04), and the user can merge sessions or re-split one before confirming. A night's frames with no pointing show as one session, with no framing split. It shows each new light session's darks, flats and bias as pinned automatically, as suggested for the user to confirm, or as not found. For a kind not found, the user adds calibration files to this import, chooses No…, or leaves it for later. A session whose calibration is not settled after Import waits in "Needs calibration" (LIB-FR-17), which Home's Pending work counts, and no Project can add it until it is settled (PRJ-FR-09). (D-W105, D-W107)
- **LIB-FR-25**: Calibration imported later fills only sessions that are still waiting and never replaces a pinned assignment. Its import review lists what each new set will calibrate, such as "Used for: Ha · 12 Oct, Ha · 13 Oct" (provisional copy), and shows matches outside the window or with unknown rotation as suggestions. Sessions set to No flats, No darks or No bias are offered with an unticked "Also use for these sessions". Provisional: "Add flats…" on a waiting session opens Import for the files the user picks. Reassigning a session's calibration is always allowed. It creates labelled pending changes on the open Projects that hold the session (VSEL-FR-12), never on Closed ones. (D-W106)
- **LIB-FR-26**: A session records the rig version it was captured with (PLAN-EQ-FR-07), and a later edit to the rig never changes it. Darks and bias match a session by its camera: by model when the rigs hold only one camera of that model, and otherwise by the camera alias the import linked them to; a camera confirmed at import counts as the explicit match (PLAN-EQ-FR-08). A camera's defaults "Don't use darks" and "Don't use bias" settle its sessions as No darks or No bias automatically, with no warning, and the user can override them per session. (D-W104)
- **LIB-FR-27**: Leaving first-run setup by any exit (finishing it, Index later or Set up later) hands over to Home and opens a modal orientation walk once. The walk has one stop per main navigation entry (LIB-FR-10), in navigation order, with Home's stop last, and each stop brings its page into view. Next and Back move between stops, and Skip or Escape closes the walk. Finishing or skipping it ends it, and it never opens by itself again. Settings > Help replays it from its first stop (LIB-FR-21). The walk creates and changes no record. (D-W117)

### Key Entities

Use the [root vocabulary](../063-clean-rebuild-contract/spec.md#key-entities). Feature-specific evidence and decisions retain their input identity, scope, and revision. This feature adds:

- **Project**: the processing unit of PV-PRJ. A session joins a Project only when the user adds it, and several Projects may hold the same session.
- **Rig**: an optical train with dated versions. A session has one rig, taken from its confirmed equipment association, and keeps the version it was captured with.
- **Calibration assignment**: the darks, flats and bias pinned on a light session at ingestion, or a No choice for a kind. A session is settled when every kind has one. (D-W101, D-W105)
- **Trashed frame**: a catalog record kept for traceability after its file went to the OS Trash. It is hidden from every query and total except the Sessions "Trashed" filter and a Closed Project that held it when it was trashed. (D-W43, D-W52, D-W97)
- **Network volume**: a location on an OS-mounted network share, flagged in its row, hashed resumably and read Offline when unmounted.
