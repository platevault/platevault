# Workflow re-architecture: decisions log (grilling, 2026-10-06)

## Settled
- D-W1 (runs replaced by D-W94): The Project is the top-level container. Every processing run lives inside a Project.
- D-W3 (stage names amended by D-W76; Review step removed by D-W78; runs replaced by D-W94): The UI renames "View" to "processing run". A Project holds several runs, and the pipeline (Select, Review, Calibrate, Prepare, Results, Done) belongs to each run.
- D-W4 (Results folder and attach replaced by D-W98; outputs as inputs dropped by D-W93): Results are discovered from the run's output folder. Manual attach is a visible secondary action, not hidden. A run's outputs can be picked as inputs to another run through the input filters when that run is created.
- D-W5 (table placement amended by D-W82; matching moved to ingestion by D-W101): Calibration is automatic by default. The step shows a readiness line, the full requirement table sits behind "Review matches", and new masters found in Results are offered once.
- D-W7 (Home superseded by D-W39): Home is the Projects list, with one line highlighting sessions that need a Target or belong to no Project (no Inbox, per D-W33). A Project page has a stage rail. Planning has its own workflow page, and Import has its own workflow entry.
- D-W8 (superseded by D-W93 and D-W94): A run belongs to exactly one Project. Reuse across Projects goes through Results as inputs.
- D-W9 (one subject per run and mosaic subjects replaced by D-W94 and D-W95): A Project is a campaign that can hold several subjects (Targets or mosaics), with no limit on how far apart they are. Each run has exactly one subject. Several objects in one field count as one Target, with the others listed as aliases or "also in field". Goals are set per subject and channel.
- D-W10 (superseded by D-W33/D-W34): sessions are assigned only to processing runs. A Project has no session list of its own.
- D-W11: Import works like Lightroom. The user picks any source (local, removable or network), sees a preview of the templated destination paths in Captures or Calibration storage, and chooses Copy or Move (copy, verify SHA-256, then send the source to the OS Trash). Sources can be saved, with "Import new" skipping files already imported. "Add existing library folder" indexes in place for archives that are already organised. "File into library" is dropped. Archive stays.
- D-W12: Network paths must already be mounted by the OS. They are flagged as network volumes, hashed resumably with progress, and read as Offline when unmounted.
- D-W13: Frame review layout: preview with zoom, pan and fullscreen; plots across the session in the bottom strip; histogram and star cutouts; multi-select with threshold selection; compare mode. The frame table layout gets its own decision in round 3.
- D-W14: Lightroom-style hotkeys: ←/→ or J/K, P, X, U, Z, F, C, ⌘A, Shift+P/X, with auto-advance after marking. The list can be filtered to Picked, Rejected or Unreviewed only.
- D-W15: Frame names use a display template with presets. Columns can be selected and sorted, and the full path shows on hover and in the inspector.
- D-W16: Planning works on Targets, independent of Projects. Each Project page shows planning for its own subjects, with "Open in Planner".
- D-W17: The Targets page defaults to "My targets". Browse catalogues needs a catalogue or a preset. Search covers My targets, the bundled catalogues and SIMBAD, and offers "Add to targets" inline.
- D-W18: The Targets table uses the legacy columns: ★, Designation, Type, Max alt, Lunar, Img time, Filters (7-band strip), Opposition, Sessions, plus a compact Captured column per channel. Moon illumination appears once, in the toolbar.
- D-W19: Built-in presets are Best tonight (broadband), Narrowband (Moon up), Emission nebulae Ha, Galaxies dark sky, and Planetary nebulae OIII, plus user-saved presets. "Avoid tonight" is dropped. Field of view and mosaic presets are settled in D-W23.
- D-W20 (editor replaced by D-W84): Naming templates come back unchanged: 9 tokens with fallbacks, per-type defaults, chip editor and live preview, used by Import and Archive.
- D-W21 (superseded by D-W38): Mosaic processing is chosen per run: panel runs plus an assembly run that takes the panel Results, or one whole-mosaic run. A panel run's subject is "panel N of mosaic M".
- D-W22: The frame table stays at the top across the full width. T and a visible toolbar control cycle it through three heights: full height, about 8 rows (resizable with a drag handle), and a one-line strip showing the current frame. ⌥1-4 filters it (All, Picked, Rejected, Unreviewed). The preview and plots fill the rest, and F gives fullscreen.
- D-W23: An optical train selector in the Targets toolbar adds a Fit column (fits / N panels / tiny) and the presets Mosaic candidates (≥2 panels) and Fits nicely (25-90% of the field). The train also filters which bands are shown: no narrowband filters when the train has none.
- D-W24: Import routing: lights go to Captures storage and appear in Sessions (no Inbox); calibration frames go to the Calibration library; frames with no type are held as Unclassified in the import review; duplicates by SHA-256 are skipped; files still being written are held back until they settle.
- D-W25 (superseded by D-W33): no Inbox. Sessions highlights "Needs a Target" and "Not in any Project", the latter offering Create Project or Add to Project as a subject.
- D-W26 (Project close and sheet replaced by D-W80; run Clean up amended by D-W81; runs replaced by D-W94): The user marks a run Complete, then gets Clean up (unchanged: removes prepared links, clones and copies). The user marks a Project Done, then gets Archive, which keeps any session that another open Project still uses. The Project's Done / Archive sheet also offers to trash rejected frames (D-W43).
- D-W27: Home shows one row per Project with its goal progress, stage and a single Next action, chosen as described in D-W35.
- D-W29 (goal kinds amended by D-W90): Goal kinds are integration per channel, frame count per channel, and a quality bar (e.g. median FWHM limit, or only Usable frames count). Mosaic panels carry their own integration goals. Missing calibration and exposure mismatch are automatic warnings, not goals. The mixed-equipment warning is gone, because runs are single-rig under D-W37. Exposure preference and the separate equipment goal are dropped. Spread over nights and moon limit are deferred.
- D-W30: Settings > Goal templates provides built-in templates (HOO, SHO, LRGB, OSC broadband, OSC dual-band) plus user templates. Applying a template copies its values into the Project, where they stand alone and stay editable. Templates are not filtered by optical train.
- D-W31 (ownership superseded by D-W87): In Settings > Equipment, filters are attached to the optical train as a simple list, which works for mono or OSC with any number of filters. Mono or OSC comes from the camera. The train's filters drive the Targets band strip, the Targets filter presets (a narrowband preset is hidden when the train has no narrowband filter) and the Fit column. They never filter Goal templates (D-W30). An unknown header filter prompts the user to add it to the train.
- D-W32 (superseded by D-W37): Each subject has one primary optical train.
- D-W28: The contract is amended first (specs and journeys PR), then the backend deltas, then the final UI built from the harness tokens.
- D-W33 (candidate rule narrowed by D-W37; derived candidates and the run picker replaced by D-W94 and D-W96): The Inbox is dropped. A Project's CANDIDATE sessions are derived: every session whose Target is one of the Project's subjects and whose rig is one of the Project's rigs. Nothing is assigned at the Project level. A run's session picker starts from the subject's candidates on the run's rig.
- D-W34 (superseded by D-W94 and D-W96): Sessions are explicitly assigned only to processing runs, as each run's revisioned membership. A Project's MEMBERS are inherited from its runs. Goals count members only. There is no per-subject optical-train switch; rigs are listed per Project and each run uses one rig (D-W37).
- D-W35 (first rule superseded by D-W78, top line by D-W89; runs replaced by D-W94): Home's Next action takes the first that applies: new candidate sessions ("Review N new frames", opening review filtered to Unreviewed), then a blocked run, then "Plan tonight" when goals are unmet and a window exists, then "Start a processing run". - D-W36 (counting basis replaced by D-W96; runs replaced by D-W94): Goal progress shows two labelled numbers per goal: "in project" (sessions in the Project's runs; counts toward the goal) and "captured" (all candidate sessions), e.g. `Ha 6h10 in project · 9h15 captured · goal 10h`. - D-W37 (one rig per run replaced by groups, D-W94 and D-W95): A Project lists every rig (optical train) taking part. Candidates are sessions whose Target is a subject AND whose rig is one of the Project's rigs. Each run uses exactly one rig, and its session picker offers only that rig's sessions, so no run mixes equipment. The Targets rig selector can choose "this Project's rigs".
- D-W38 (Review all removed by D-W78; superseded by D-W95): Mosaic mode. A subject can be marked Mosaic, with panels given by centre and rotation. Each session is assigned to a panel by its pointing, checked against the panel centre; ambiguous or off-panel sessions are flagged for the user. A run on a mosaic subject creates a RUN GROUP: one run per panel, sharing one setup (profile, input mode, calibration policy), prepared under <output>/<Project>/<Mosaic>/Panel N/ so WBPP can load the parent folder. Each panel run has its own status, and group actions (Review all, Prepare all) act on every panel. Assembly is optional, done in the application, and comes back as a group Result. The single whole-mosaic run is dropped (supersedes D-W21 option b).
- D-W39 (superseded by D-W89): Home is a control-panel dashboard with six sections: (1) actions: Import, New Project, Plan tonight; (2) Projects, each with goals (in project / captured), stage and Next; (3) new sessions needing work, grouped as needs a Target / not in a Project / unreviewed / ready to add to a run, each with a one-click action; (4) Tonight: best windows for subjects and favourites, the Moon, the darkness window; (5) Target status: unmet goals and what each channel still needs; (6) running work.
- D-W40: Frame review offers three views of the same list: the table, a filmstrip (the table's one-line state, with thumbnails), and a grid (G, Lightroom-style culling with multi-select). All three share the same hotkeys. Thumbnails come from the 067 decoder and are cached.
- D-W41 (frame review part superseded by D-W78; the rest by D-W95 and D-W101): In a mosaic run group, frame review can span every panel, with a panel column and filter. Calibration is matched per panel run.
- D-W42 (superseded by D-W79): Quality has two levels. Library quality (P/X/U) is global. "Reject for this Project only" is a secondary action using the Project-scoped reject, and "in project" excludes Project-rejected frames.
- D-W43 (the sheet is replaced by Wrap up's Trash step, D-W80; run refusals adapted to Projects by D-W94, Project-only rejects removed by D-W79 and the Result-input refusal dropped by D-W93): Trashing rejected frames is part of the Project's Done / Archive cleanup (D-W26), not a separate action, and not part of a run's Clean up. Files go to the OS Trash only, with no permanent delete; the 071 custody rules apply. The sheet lists the frames it refuses, with the reason: used in a prepared revision of a run that is not Complete (any Project), or a recorded input of a Result. A Trashed record stays for traceability but is hidden everywhere else: run pickers, candidates, frame review, Sessions, Targets, Home, overviews, goals and totals.
