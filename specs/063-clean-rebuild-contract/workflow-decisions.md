# Workflow re-architecture: decisions log (grilling, 2026-10-06)

## Settled
- D-W1: The Project is the top-level container. Every processing run lives inside a Project.
- D-W3: The UI renames "View" to "processing run". A Project holds several runs, and the pipeline (Select, Review, Calibrate, Prepare, Results, Done) belongs to each run.
- D-W4: Results are discovered from the run's output folder. Manual attach is a visible secondary action, not hidden. A run's outputs can be picked as inputs to another run through the input filters when that run is created.
- D-W5: Calibration is automatic by default. The step shows a readiness line, the full requirement table sits behind "Review matches", and new masters found in Results are offered once.
- D-W7 (Home superseded by D-W39): Home is the Projects list, with one line highlighting sessions that need a Target or belong to no Project (no Inbox, per D-W33). A Project page has a stage rail. Planning has its own workflow page, and Import has its own workflow entry.
- D-W8: A run belongs to exactly one Project. Reuse across Projects goes through Results as inputs.
- D-W9: A Project is a campaign that can hold several subjects (Targets or mosaics), with no limit on how far apart they are. Each run has exactly one subject. Several objects in one field count as one Target, with the others listed as aliases or "also in field". Goals are set per subject and channel.
- D-W10 (superseded by D-W33/D-W34): sessions are assigned only to processing runs. A Project has no session list of its own.
- D-W11: Import works like Lightroom. The user picks any source (local, removable or network), sees a preview of the templated destination paths in Captures or Calibration storage, and chooses Copy or Move (copy, verify SHA-256, then send the source to the OS Trash). Sources can be saved, with "Import new" skipping files already imported. "Add existing library folder" indexes in place for archives that are already organised. "File into library" is dropped. Archive stays.
- D-W12: Network paths must already be mounted by the OS. They are flagged as network volumes, hashed resumably with progress, and read as Offline when unmounted.
- D-W13: Frame review layout: preview with zoom, pan and fullscreen; plots across the session in the bottom strip; histogram and star cutouts; multi-select with threshold selection; compare mode. The frame table layout gets its own decision in round 3.
- D-W14: Lightroom-style hotkeys: ←/→ or J/K, P, X, U, Z, F, C, ⌘A, Shift+P/X, with auto-advance after marking. The list can be filtered to Picked, Rejected or Unreviewed only.
- D-W15: Frame names use a display template with presets. Columns can be selected and sorted, and the full path shows on hover and in the inspector.
- D-W16: Planning works on Targets, independent of Projects. Each Project page shows planning for its own subjects, with "Open in Planner".
- D-W17: The Targets page defaults to "My targets". Browse catalogues needs a catalogue or a preset. Search covers My targets, the bundled catalogues and SIMBAD, and offers "Add to targets" inline.
- D-W18: The Targets table uses the legacy columns: ★, Designation, Type, Max alt, Lunar, Img time, Filters (7-band strip), Opposition, Sessions, plus a compact Captured column per channel. Moon illumination appears once, in the toolbar.
- D-W19: Built-in presets are Best tonight (broadband), Narrowband (Moon up), Emission nebulae Ha, Galaxies dark sky, and Planetary nebulae OIII, plus user-saved presets. "Avoid tonight" is dropped. Field of view and mosaic presets are settled in D-W23.
- D-W20: Naming templates come back unchanged: 9 tokens with fallbacks, per-type defaults, chip editor and live preview, used by Import and Archive.
- D-W21 (superseded by D-W38): Mosaic processing is chosen per run: panel runs plus an assembly run that takes the panel Results, or one whole-mosaic run. A panel run's subject is "panel N of mosaic M".
- D-W22: The frame table stays at the top across the full width. T and a visible toolbar control cycle it through three heights: full height, about 8 rows (resizable with a drag handle), and a one-line strip showing the current frame. ⌥1-4 filters it (All, Picked, Rejected, Unreviewed). The preview and plots fill the rest, and F gives fullscreen.
- D-W23: An optical train selector in the Targets toolbar adds a Fit column (fits / N panels / tiny) and the presets Mosaic candidates (≥2 panels) and Fits nicely (25-90% of the field). The train also filters which bands are shown: no narrowband filters when the train has none.
- D-W24: Import routing: lights go to Captures storage and appear in Sessions (no Inbox); calibration frames go to the Calibration library; frames with no type are held as Unclassified in the import review; duplicates by SHA-256 are skipped; files still being written are held back until they settle.
- D-W25 (superseded by D-W33): no Inbox. Sessions highlights "Needs a Target" and "Not in any Project", the latter offering Create Project or Add to Project as a subject.
- D-W26: The user marks a run Complete, then gets Clean up (unchanged: removes prepared links, clones and copies). The user marks a Project Done, then gets Archive, which keeps any session that another open Project still uses. The Project's Done / Archive sheet also offers to trash rejected frames (D-W43).
- D-W27: Home shows one row per Project with its goal progress, stage and a single Next action, chosen as described in D-W35.
- D-W29: Goal kinds are integration per channel, frame count per channel, and a quality bar (e.g. median FWHM limit, or only Usable frames count). Mosaic panels carry their own integration goals. Missing calibration and exposure mismatch are automatic warnings, not goals. The mixed-equipment warning is gone, because runs are single-rig under D-W37. Exposure preference and the separate equipment goal are dropped. Spread over nights and moon limit are deferred.
- D-W30: Settings > Goal templates provides built-in templates (HOO, SHO, LRGB, OSC broadband, OSC dual-band) plus user templates. Applying a template copies its values into the Project, where they stand alone and stay editable. Templates are not filtered by optical train.
- D-W31: In Settings > Equipment, filters are attached to the optical train as a simple list, which works for mono or OSC with any number of filters. Mono or OSC comes from the camera. The train's filters drive the Targets band strip, the Targets filter presets (a narrowband preset is hidden when the train has no narrowband filter) and the Fit column. They never filter Goal templates (D-W30). An unknown header filter prompts the user to add it to the train.
- D-W32 (superseded by D-W37): Each subject has one primary optical train.
- D-W28: The contract is amended first (specs and journeys PR), then the backend deltas, then the final UI built from the harness tokens.
- D-W33 (candidate rule narrowed by D-W37): The Inbox is dropped. A Project's CANDIDATE sessions are derived: every session whose Target is one of the Project's subjects and whose rig is one of the Project's rigs. Nothing is assigned at the Project level. A run's session picker starts from the subject's candidates on the run's rig.
- D-W34: Sessions are explicitly assigned only to processing runs, as each run's revisioned membership. A Project's MEMBERS are inherited from its runs. Goals count members only. There is no per-subject optical-train switch; rigs are listed per Project and each run uses one rig (D-W37).
- D-W35: Home's Next action takes the first that applies: new candidate sessions ("Review N new frames", opening review filtered to Unreviewed), then a blocked run, then "Plan tonight" when goals are unmet and a window exists, then "Start a processing run". Home's top line reads "N sessions need a Target · M not in any Project".
- D-W36: Goal progress shows two labelled numbers per goal: "in project" (sessions in the Project's runs; counts toward the goal) and "captured" (all candidate sessions), e.g. `Ha 6h10 in project · 9h15 captured · goal 10h`. "Goal met" and Home's Next rule use "in project" only. The UI never says "not in a run".
- D-W37: A Project lists every rig (optical train) taking part. Candidates are sessions whose Target is a subject AND whose rig is one of the Project's rigs. Each run uses exactly one rig, and its session picker offers only that rig's sessions, so no run mixes equipment. The Targets rig selector can choose "this Project's rigs".
- D-W38: Mosaic mode. A subject can be marked Mosaic, with panels given by centre and rotation. Each session is assigned to a panel by its pointing, checked against the panel centre; ambiguous or off-panel sessions are flagged for the user. A run on a mosaic subject creates a RUN GROUP: one run per panel, sharing one setup (profile, input mode, calibration policy), prepared under <output>/<Project>/<Mosaic>/Panel N/ so WBPP can load the parent folder. Each panel run has its own status, and group actions (Review all, Prepare all) act on every panel. Assembly is optional, done in the application, and comes back as a group Result. The single whole-mosaic run is dropped (supersedes D-W21 option b).
- D-W39: Home is a control-panel dashboard with six sections: (1) actions: Import, New Project, Plan tonight; (2) Projects, each with goals (in project / captured), stage and Next; (3) new sessions needing work, grouped as needs a Target / not in a Project / unreviewed / ready to add to a run, each with a one-click action; (4) Tonight: best windows for subjects and favourites, the Moon, the darkness window; (5) Target status: unmet goals and what each channel still needs; (6) running work.
- D-W40: Frame review offers three views of the same list: the table, a filmstrip (the table's one-line state, with thumbnails), and a grid (G, Lightroom-style culling with multi-select). All three share the same hotkeys. Thumbnails come from the 067 decoder and are cached.
- D-W41: In a mosaic run group, frame review can span every panel, with a panel column and filter. Calibration is matched per panel run.
- D-W42: Quality has two levels. Library quality (P/X/U) is global. "Reject for this Project only" is a secondary action using the Project-scoped reject, and "in project" excludes Project-rejected frames.
- D-W43: Trashing rejected frames is part of the Project's Done / Archive cleanup (D-W26), not a separate action, and not part of a run's Clean up. The sheet offers "Move N rejected frames to Trash (size)", covering the Project's candidates that are library-Unusable; Project-only rejects are never included. Files go to the OS Trash only, with no permanent delete; the 071 custody rules apply. The sheet lists the frames it refuses, with the reason: used in a prepared revision of a run that is not Complete (any Project), or a recorded input of a Result. A Trashed record stays for traceability but is hidden everywhere else: run pickers, candidates, frame review, Sessions, Targets, Home, overviews, goals and totals. It appears only under a "Trashed" filter in Sessions. Undo is "Put back" in the OS Trash; a rescan restores the record as Unusable.

## Settled in round 6 (2026-10-06, all recommendations accepted)
- D-W44: "In project" counts the frames in a run's saved membership, minus frames excluded from that run and frames rejected for the Project.
- D-W45: A run member that stops being a candidate (its Target is re-confirmed, or its rig is removed) stays in the run and still counts "in project". The run's Refresh flags it as "no longer matches subject" and offers to remove it.
- D-W46: For Archive, "another open Project still uses" means a member of a run in a Project that is not Done; being a candidate does not count. Mark Done asks the user to complete or abandon open runs first. A Done Project can be Reopened.
- D-W47: Built-in goal template values, all editable after applying: HOO Ha 10h + OIII 10h; SHO Ha/OIII/SII 10h each; LRGB L 6h + R/G/B 2h each; OSC broadband 10h; OSC dual-band 15h.
- D-W48: Home hides Done Projects behind a "Show done" filter. A "blocked run" is a run waiting on the user: unresolved inputs, calibration needing review, or a failed preparation.
- D-W49: The run picker starts with every available candidate selected.
- D-W50: A run's subject and rig are fixed at creation. Another subject or rig needs another run.
- D-W51: A single run prepares to <output>/<Project>/<Run>/. Each new prepared revision gets a new folder (<Run> (rev 2)/); an existing prepared folder is never reused. Results go to a sibling <Run> Results/ folder, so WBPP never reads its own output as input. A mosaic group prepares to <output>/<Project>/<Mosaic>/Panel N/, with <Mosaic> Results/ as a sibling.
- D-W52: A frame trashed after its run is Complete still shows in that run's fixed membership, marked "Trashed". It is hidden everywhere else.
- D-W53: Shift+P and Shift+X mark the frame and move to the next one, even when auto-advance is off. Auto-advance is on by default.
- D-W54: Rejecting a frame in a run's Review step removes it from that run's draft with the reason "Rejected"; un-rejecting restores it. Prepared revisions are unchanged.
- D-W55: The calibration policy is automatic assignment on (the default) or off. A master found in a run's Results is offered once, in that run's Results step.
- D-W56: Results from runs on another rig may be inputs to a run, shown with their rig. The one-rig rule applies to raw frames only.
- D-W57: Trashing a frame with copies in two locations moves every copy. If any copy is refused, the whole frame is refused.
- D-W58: The legacy "Auto-apply pattern" checkbox and the generic project folder pattern are dropped; runs own the output layout.
- D-W59: Adding a "Not in any Project" session to a Project also adds its rig if the Project lacks it, with a visible note.
- D-W60: "My targets" lists the ★ favourites plus every subject of an open Project, which carries a Project badge.
- D-W61: Fit compares the Target's major axis with the shorter side of the field of view.
- D-W62: With several Project rigs, the list shows one Fit per rig and the union of their bands, and presets match when any rig fits.
- D-W63: Tonight's windows for a mosaic use the mosaic's centre; the Plan area lists each panel.

## Round 7 (2026-10-06): recommendations applied by default after the user said "continue please"; any of them can be reverted before the contract PR lands
- D-W64: A run can be marked Abandoned. An Abandoned run is kept read-only, its frames stop counting "in project", and it can be Reopened.
- D-W65: A rig cannot be removed from a Project while any run that is not Abandoned uses it. Under D-W45, a member of a run that is not Abandoned stops being a candidate only when its own rig or Target changes. Removing a subject or rig that no run uses, or that only an Abandoned run uses, takes the matching sessions out of the candidates. Reopening an Abandoned run is refused while its subject or rig is not on the Project, and the refusal names each missing item.
- D-W66: "Captured" means candidates plus run members, so "in project" never exceeds "captured" (refines D-W36).
- D-W67: A mosaic group's new prepared revision goes to <Mosaic> (rev 2)/ with Panel N/ folders inside it. <Run> Results/ is one folder shared by all revisions of the run; each discovered Result records the revision it came from.
- D-W68: Results in <Mosaic> Results/ are assigned to a panel by a Panel N/ subfolder or by evidence from the processing tool (header or file name). Otherwise the user places them.
- D-W69: A Project can be Reopened after Archive. Archived sessions show as Archived until the user restores them; reopening moves no files.
- D-W70: The Project Done / Archive sheet also offers "Move N processing intermediates to Trash (size)". Final Results and adopted masters are kept, and the D-W43 trash rules apply.
- D-W71 (lead consistency default, follows from D-W64/D-W65; revertible): Abandoned behaves like Complete for every gate. Mark Abandoned is blocked while an operation is Running. An Abandoned run gets Clean up. Reopen returns the run to the stage it was in. Its accepted Results stay reusable as inputs, and its members still count as "captured". The trash refusal reads "a prepared revision of a run that is neither Complete nor Abandoned". A subject, like a rig, cannot be removed while a run that is not Abandoned uses it.

## Round 7 answered by the user (2026-10-07)
The user accepted D-W65, D-W66, D-W67 and D-W69 and changed the others. The entries below supersede D-W64, D-W68 and D-W71, and they narrow D-W65, D-W66 and D-W70. Every "Abandoned" rule above is dead.
- D-W72 (replaces D-W64 and D-W71): No Abandoned state. A run that is no longer wanted is deleted. **Delete run** is refused while an operation is Running, and refused while one of its accepted Results is an input to another run. It shows what goes: the run record, its prepared folders (moved to the OS Trash) and, only when ticked, its Results folder (also to the OS Trash). Library frames and quality decisions are never touched. After deletion its members stop counting "in project" and "captured", unless they are still candidates. There is no in-app undo; Put back in the OS Trash restores files only. Mark Done asks the user to complete or delete each open run.
- D-W65 (narrowed by D-W72): A rig or subject cannot be removed from a Project while any run uses it. A run member stops being a candidate only when its own rig or Target changes.
- D-W66 (narrowed by D-W72): "Captured" means candidates plus members of the Project's existing runs.
- D-W73 (replaces D-W68): Panels are set explicitly when the mosaic run group is created. Each panel run writes to its own Results folder, `<Mosaic>/Panel N Results/`, so a Result's panel is known from where it was written. The assembled mosaic goes to `<Mosaic> Results/` as the group Result. There is no header or file-name inference.
- D-W74 (extends D-W70): The Done / Archive sheet also offers "Move N duplicate copies to Trash (size)". These are byte-identical (SHA-256) extra physical copies of the Project's frames. One copy is always kept: the copy in Captures or Calibration library storage, otherwise the copy in the earliest-registered location. Each copy is rehashed before it moves, and the D-W43 trash rules apply.
