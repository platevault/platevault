# View selection research

## Decision

Store Views as Tier 1 records in the clean library catalog, `crates/persistence/library`, through its single serialized writer. A View keeps immutable committed membership revisions and at most one durable draft. Geometry evidence comes from pure `platevault_core::view_geometry` code over target-match footprints. Candidate filtering, preselection, summaries and refresh differences are pure `platevault_core::view_selection` functions over one catalog snapshot. Quality actions reuse the library quality writer and the 065 Project rejection writer inside one scoped transaction. The isolated rebuilt shell exposes `view_*` commands. The plan reuses no legacy prepared View, source View or project command.

## Source evidence

Read at `97ca51be39cf970be23e22fcbf22c60c7963b40c`: the reviewed 064 backend plus the 065 plan, which has no code yet. No runtime behavior is claimed from reading.

- Catalog durability: `Catalog::open` opens one writer with WAL, FULL synchronous, foreign keys and macOS fullfsync, then a read-only pool. `write_txn!` runs `BEGIN IMMEDIATE` and commits (`crates/persistence/library/src/lib.rs:54-64`, `:324-347`).
- Schema versioning: `SCHEMA_VERSION` is 6. `install_schema` refuses any other recorded version before DDL and has no migration chain (`lib.rs:46`, `:2066-2102`). The 065 plan sets version 7.
- Sessions and captures: `SessionQuery` filters only by location (`lib.rs:138-143`). `Catalog::session` returns assets, D16 members, associations and lineage (`lib.rs:973-985`). `SessionMember` names every physical copy and its applicable quality (`lib.rs:179-186`). `CaptureView` groups logical captures, and `capture_quality` derives ConflictingCopies and pending states (`lib.rs:5145-5278`). `is_light` reads the effective IMAGETYP (`lib.rs:5134-5140`).
- CAS helpers: `check_expected_assets` refuses stale revisions, changed fingerprints and Retired copies (`lib.rs:4334-4366`). `check_expected_sessions` returns Conflict with lineage successors (`lib.rs:4882-4910`). `SuggestedAssociation` and `assessed_current` bind evidence to the exact member observations and decision revisions it was computed from (`lib.rs:217-232`, `:4957`).
- Quality: `Catalog::set_quality` hashes outside the transaction through `current_digests`, then checks and decides inside one `write_txn!` (`lib.rs:1148-1179`, `:1221`). `ApplicableQuality` names Unreviewed, Usable, Unusable, ChangedContent, VerificationPending, Conflicting and ConflictingCopies (`crates/platevault-model/src/lib.rs:359-377`).
- Geometry inputs: `CaptureMetadata` carries pointing, WCS pointing, `sky_rotation_deg`, focal length, pixel size, dimensions and binning (`model/src/lib.rs:415-445`). `sky_rotation_deg` takes the WCS rotation, else OBJCTROT (`model/src/lib.rs:520`). The FITS reader maps RA/DEC or OBJCTRA/OBJCTDEC, OBJCTROT, FOCALLEN, XPIXSZ and WCS CRVAL (`crates/metadata/fits/src/lib.rs:209-254`). `Equipment` holds `focal_length_mm` and `pixel_size_um` (`model/src/lib.rs:865-875`).
- Existing association geometry: `assess_target` needs an agreeing OBJECT alias for a Suggested Target association. `frame_pointing` prefers the plate-solved centre, and `inscribed_radius` keeps binning at 1×1 so it never overstates the field (`crates/platevault-core/src/targets.rs:873-1001`).
- Shared footprint math: target-match 0.5.1 provides `SkyFootprint::new`, `compare_footprints` with `normalized_coverage` and `centre_separation`, and `Membership::Rotated` for `is_framed` (`footprint.rs:144`, `:233-264`; `matcher.rs:106-124`). Its re-exported skymath 0.6 has `gnomonic_unproject` (`coords.rs:563`).
- Reference seam: the `AssetReferences` trait names VSEL as an implementer. Retire review reads every registered source and reads it again on confirmation (`crates/platevault-core/src/library.rs:32-46`, `:195-241`). `ReferenceKind::View` covers fixed memberships and prepared revisions (`model/src/lib.rs:965-985`). The LIB-AC-16 test serves a fake fixed View and a fake prepared revision (`crates/platevault-core/tests/library.rs:987-1010`, `:1125-1243`).
- IPC: handlers take `State<Arc<Library>>` and return `Result<T, ErrorResponse>` through `fail` and `report` (`apps/desktop/src-tauri/src/commands/library.rs:28-51`). `library_set_quality` calls the catalog with `InventoryProbe` (`:234-240`). The isolated shell registers its handlers with `generate_handler!` (`apps/desktop/src-tauri/src/library_shell.rs:72-98`). The dev bridge compiles only with `dev-tools` and binds IPv4 loopback (`:23-27`, `:164-188`).
- Fixtures: the shared writers emit 4×4 FITS and XISF images with caller keywords (`crates/platevault-core/tests/support/mod.rs:6-77`).
- Legacy surface: `commands/prepared_views.rs` defines `preparedview_*` and `sourceview_*` over the old application state. The isolated shell does not register them.

## Cross-spec seams

Each seam names the interface VSEL needs from a sibling and the default VSEL uses until that sibling lands.

- **S1 PRJ (065, plan only at this base).** VSEL reads `Catalog::project` for framing snapshots, panels, equipment IDs and the Project revision. Reject for Project needs the body of `Catalog::set_project_rejection` as a crate-private function that runs inside a caller's transaction. Default: the VSEL catalog owner extracts that body without behavior change if 065 did not. VSEL also fills the `views` field that 065 reserves for `project_detail`.
- **S2 PREP (069).** PREP owns profile identities and the per-View handoff settings, including the profile choice, keyed by View ID. It also owns Review preparation, exact-membership confirmation (D02), prepared revisions and their references under kind View. It needs `view_revision` with exact members, copies, review bases, states, reasons and changed inputs, plus the unresolved members and open choices of `view_detail`. Default: `view_detail` reads the profile from the PREP handoff record, which is absent, so the profile reads unset. No prepared revision exists. The prepared-revision parts of VSEL-AC-05 and VSEL-AC-12 are verified with 069.
- **S3 PIX (067).** The frames area shares the draft. PIX needs member asset IDs and never edits membership. VSEL needs per-session measurement summaries for measurement columns. Default: `measurements` is null and reads Not measured; no VSEL read starts measurement.
- **S4 CAL (068).** The calibration area reads the included light members of the draft through `view_membership` or of a revision through `view_revision`. CAL keys its decisions by `(view_id, revision)`, a foreign key to `view_revisions`, and reuses a decision only while the session's included asset set is unchanged (CAL-FR-08). Excluding a session from Calibration edits the VSEL draft; only Save creates a revision. Default: VSEL stores no calibration choice.
- **S5 RES (070).** RES owns Complete and Reopen as append-only rows. It adds `require_view_open(conn, view_id)` inside the VSEL save transaction, the one place a membership revision is created. RES adds product inputs as their own input class keyed by the revision row, and copies them when a draft starts from a revision. Default: every View is open and has no product input.
- **S6 STO (071).** Archive and filing repair paths without changing asset IDs, so View membership needs no change and STO writes no View row. STO reads committed members for View footprints, and archived copies read Offline and therefore unresolved. STO defines its own custody-facts source and implements the View adapter over `Catalog::view`, `Catalog::list_views` and `Catalog::view_revision`, with completion from RES and running operations from PREP and STO. Default: VSEL implements no STO trait.

PLAN (072) has no seam with VSEL.

## Resolved ambiguities

Each entry records the decision, its basis and the alternative considered. Where the spec is silent, the default follows the root [decision register](../063-clean-rebuild-contract/decisions.md).

- **R1 Storage and schema version.** View tables live in `crates/persistence/library/src/views.sql`, appended to the catalog schema, with SQL in `src/views.rs`. Dependency order is 064 (version 6), then 065 (version 7), then 066. VSEL takes the version after the integrated base: 8 when it lands directly on 065. If another schema-bearing feature lands first, VSEL takes the next free number, and its refusal test uses the base version. Basis: Views reference `projects`, `targets`, `sessions` and `assets` rows, and Reject for Project writes Project rows in the same transaction. Alternative: a separate persistence crate needs a second writer.
- **R2 Drafts and revisions (D08).** A View has committed membership revisions numbered from 1 and at most one durable draft. A draft carries its own draft revision and the base revision it started from. Every draft edit commits synchronously as recoverable unsaved work, never as the committed membership. Save View promotes the draft to the next revision only when its base is still current. A never-saved View has revision 0, and discarding its draft deletes the View. Basis: J22 S16 requires restart to show the committed revision and the unsaved work separately. Alternatives: a frontend-only draft loses unfinished work at restart, and autosave into revisions breaks explicit Save.
- **R3 Immutability.** SQLite triggers refuse UPDATE and DELETE on committed revision rows and their session and member rows. Save changes a draft row into a committed row in one statement. Basis: VSEL-AC-10, VSEL-AC-12, FR-14 and D09. Alternative: code discipline alone cannot prove that a later writer leaves revisions intact.
- **R4 Origins (FR-01).** A Project origin needs a saved Project. A Target origin needs a saved Target at its expected revision; a seed Target is saved first through `library_save_target`, as 065 R2 requires. A Sessions origin takes `ExpectedSession` values, so a stale or superseded session is Conflict with successors. Creation writes View rows only: no Project, folder or quality change.
- **R5 Profile.** The View stores no profile. `view_detail` shows the profile from the PREP handoff settings keyed by View ID and reports `profile_unset` until one exists (S2). Basis: FR-02 requires an optional profile, PREP-FR-01 owns profile qualification, and one record avoids two copies that could disagree. Alternative: an opaque profile column in View revisions would duplicate the PREP setting.
- **R6 Frame geometry (FR-04, D01).** Pointing is the WCS centre, else the header RA/DEC. Orientation is `sky_rotation_deg`, read as a position angle east of north. The field of view uses header FOCALLEN and XPIXSZ with the binned pixel counts at 1×1, as `inscribed_radius` does. Without header optics, it uses the session's Confirmed equipment association: equipment focal length and pixel size, times header binning, over the binned pixel counts. Unknown binning then leaves the field of view unknown. Each input names its source. A footprint is the rotated field rectangle around the pointing, unprojected through skymath `gnomonic_unproject` into a target-match `SkyFootprint` with Direct parity. OBJECT is never read.
- **R7 Overlap criterion (D01, J21 G2).** A Target framing matches a frame when its snapshot coordinates fall inside the frame footprint through `is_framed` with `Membership::Rotated`. A panel framing matches when `compare_footprints(frame, panel).normalized_coverage` reaches `minFootprintCoverage`. The default is 0.5, valid in (0, 1], stored in the View criteria and shown with the evidence. A session matches only when every light frame matches the same framing element. A panel without a position angle has no footprint and preselects nothing. Polygon work runs only when the centre separation is at most the frame diagonal plus the panel diagonal. Alternative: centre distance alone, which FR-03 rejects.
- **R8 Pointing-only radius (FR-04).** A session whose light frames all have pointing, but at least one lacks a field of view or orientation, is pointing-only. It is listed as a suggestion when its mean pointing lies within `suggestionRadiusDeg` of a framing centre. It is ordered by that separation, has no footprint and is never preselected. The default radius is 2.0°, valid in (0, 180], stored in the criteria. Basis: FR-04 and product-flow open decision 1. Because nothing is preselected by radius, the default changes only which rows carry the label.
- **R9 Position unknown.** A session with any light frame lacking pointing reads Position unknown with counts of frames with and without pointing. It has no distance and no footprint and sorts after every row with evidence. Basis: FR-04 forbids a zero distance for unknown geometry.
- **R10 Preselection (D01, VSEL-AC-01, VSEL-AC-14).** Only a Project-origin View preselects, once at creation. A session is preselected when it matches a Project Target or panel under R7 and has a Confirmed equipment association with an equipment ID in the Project snapshot. Other equipment, observed or Suggested equipment, and every Target-origin or standalone candidate stay unselected. A Sessions origin starts with exactly the chosen sessions. Preselection writes only the draft and records the evidence that qualified it.
- **R11 Evidence binding.** A criteria-based session choice carries the member observations, observation sequences and decision revisions it was computed from, as `SuggestedAssociation` does. The catalog refuses the choice when any differs, and the Library re-reads up to three times like `ASSESSMENT_ATTEMPTS`. Basis: evidence must describe the stored session.
- **R12 Selection reasons and pins (D09).** Reasons are geometry suggestion, refresh match, manual, select matching with its filters, and origin sessions. Manual, select-matching and origin-session choices are manual inclusions. Refresh lists them as kept and never proposes their removal for falling outside the criteria.
- **R13 Session exclusions.** Deselecting a session whose reason is criteria-based, or declining a refresh addition, records an explicit session exclusion in the draft. Refresh lists it under kept exclusions instead of proposing it again. Deselecting a manual inclusion removes it. Clear selection removes every choice and records exclusions only for criteria-based ones. Basis: FR-12 keeps explicit exclusions.
- **R14 Initial frame membership (D02, FR-15).** Membership is per logical capture with its recorded copies (D16). The catalog sets the starting state from the capture's applicable quality:
  - Unreviewed or Usable starts `included`.
  - Unusable starts `excluded` with reason `library_unusable`.
  - ChangedContent, VerificationPending, Conflicting and ConflictingCopies start `excluded` with reason `quality_needs_review`, naming the state.

  Each starting exclusion stays visible, and the user can include the capture explicitly. The catalog computes the state inside the write transaction and then keeps it. Later quality decisions change no draft or revision member (VSEL-AC-10, VSEL-AC-11). Alternative: deriving states on read would let library quality move fixed membership.
- **R15 Unresolved members (FR-09, VSEL-AC-09).** Availability is live and separate from the stored state. An included capture with no Available copy is unresolved. Offline, Missing, Unreadable, IdentityConflict and Retired copies all count as unavailable. An unresolved member counts toward no included total. It is named with its session, location, availability, failure reason, paths and last-observed frames and seconds, labelled unverified. The offered actions are reconnect through `library_reselect_location`, locate through `library_review_remap`, and remove through deselection or exclusion. A member returns to the totals when its copy becomes available, with no membership change (J25 S6).
- **R16 Drift.** A member whose current fingerprint differs from its recorded basis reads changed since review. It leaves included totals and appears in the open choices (D19). Nothing resolves it automatically.
- **R17 Exclusion scope (FR-10).** Exclude from View sets the draft state to excluded with reason `view_exclusion`. Restore returns the capture to included. Files, library quality, other Views and Project records stay unchanged.
- **R18 Quality actions (FR-11, D10).** `view_quality_scope` names the scope before confirmation: library or the named Project, frames, sessions and seconds per channel. `view_apply_quality` hashes outside the transaction like `set_quality`. One writer transaction then checks the draft revision, the membership scope and the expected assets, and writes the decision. Mark included frames usable accepts only included members. Mark unusable in library accepts any member. Reject for Project needs a Project-owned View and the expected Project revision. No action changes membership, and Save never changes quality.
- **R19 Summary arithmetic (FR-08).** The channel is the exact effective FILTER text, and unknown FILTER forms its own row (065 R7). Seconds are sums of per-frame exposure rounded to whole microseconds (065 R8). Each logical capture counts once on an available copy. Unknown exposure and unknown image type are counted, never zero. Unreviewed and library-Unusable counts stay visible beside included totals.
- **R20 Candidates (FR-05, FR-06).** Candidates are current light sessions plus sessions of unknown image type, which read frame type unknown and are never suggested. Calibration sessions belong to CAL. The quality-state filter matches sessions with at least one capture in that state. Missing OBJECT matches sessions with a light frame that has no OBJECT. Temperature filters the cooler setpoint. Filters, sorting and paging change no selection. Each page reports the match count and selected sessions outside the filters. Rows without sky evidence sort last and never read 0.
- **R21 Sky coverage (FR-07).** Each footprint-class candidate returns a representative footprint: the frame nearest the session's mean pointing, plus the largest pointing spread. Panels and Target framing return their own footprints. No image is stitched. Highlighting is a frontend concern.
- **R22 Saved criteria (FR-12).** Criteria hold the framing snapshot, the equipment snapshot, `minFootprintCoverage` and `suggestionRadiusDeg`. Browsing filters are request parameters and never saved. A Project origin snapshots the Project revision, Targets, panels and equipment. A Target origin snapshots the Target coordinates at its revision. A Sessions origin has no framing, so its refresh can only report changes to existing members.
- **R23 Project context (FR-14, VSEL-AC-10).** A Project edit never changes View rows. `view_detail` reports `projectContextChanged` when the Project revision differs from the snapshot. Changing the Project association in a draft changes no criteria and selects nothing. Alternative: adopting the current Project silently would change refresh criteria without review.
- **R24 Refresh (FR-12, D09, VSEL-AC-06).** Refresh records a durable review against the latest committed revision. It lists the items below:
  - added sessions that match the criteria and are neither members nor excluded
  - added captures that joined a member session
  - removal proposals for criteria-based members whose current session fails the criteria
  - regrouped member sessions with their successors
  - unavailable members, never proposed for removal
  - manual inclusions and kept exclusions
- **R25 Accepting a refresh.** `view_apply_refresh` re-validates each accepted item and applies it to the draft, creating the draft when none exists. Declined additions become session exclusions. Keeping the View unchanged applies nothing. Save then commits the next revision. Captures added there carry `addedInRevision` and read as needing image and calibration review. Path repair keeps asset IDs, so it produces no refresh item.
- **R26 References.** `ViewReferences` implements `AssetReferences` with kind View. It names each View whose committed revisions or draft hold any asked asset. Its revision is the latest committed revision. Retired copies stay members and read unresolved. The LIB-AC-16 test replaces its fake fixed View membership with a real View and keeps the fake prepared revision until 069.
- **R27 Names.** A draft may have a blank name. Save refuses a blank trimmed name with InvalidInput naming `name`. View names need not be unique; PREP handles folder collisions.
- **R28 Errors.** Errors reuse `LibraryError` and `ErrorResponse` with no new variant. A draft Conflict carries the current draft revision, and a save Conflict carries the current committed revision; the message names which.
- **R29 Command names.** Commands use the `view_` prefix in `commands/view_selection.rs`. The legacy `preparedview_*` and `sourceview_*` commands stay unregistered in the isolated shell.
- **R30 Fixture geometry.** The worked field needs footprints of several degrees, but the shared writers emit 4×4 images. The foundation owner adds writers with declared NAXIS or XISF geometry and small data. A failing-first test confirms that both header readers report the declared dimensions before fan-out. If either reader refuses them, the fixtures scale XPIXSZ and FOCALLEN instead and label it.

## Qualification

Generated FITS and XISF fixtures must cover the worked five sessions and the 12 Sep Offline session. They also need another camera, a mismatched OBJECT, a missing OBJECT, and pointing-only and Position unknown sessions. Further cases are FOV from confirmed equipment, an unreadable frame, two new arrivals, a regroup correction, logical-capture copies, drifted and pending decisions, and SQLITE_FULL. Overlap fixtures sit at coverage of at least 0.9 or at most 0.1, so the outcome does not depend on the default. Every scenario compares source hashes before and after. Real development-MCP evidence remains an acceptance gate. No legacy test result proves the rebuild.
