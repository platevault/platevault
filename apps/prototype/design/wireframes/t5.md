# T5 wireframes: Results, storage custody and observing plans

Track T5. Specs 070 (RES), 071 (STO), 072 (PLAN); journeys J26-J30; product
flow H1-H3a, I1-I5, J, K, L, B3. Binding contracts: `HIGH-LEVEL-DESIGN.md`
(routes §4, seams §5, layout §6, tokens §7, components §8, states §9, copy §10).

Owned files: `src/features/t5/**`, `src/store/slices/t5.ts`, this file.
Every number and path below is fixture data. Nothing here claims backend
behaviour: scans, hashes, Trash, transfers, notifications and calendar files
are simulated against the in-browser disk and say so where it matters.

## Shared conventions on every T5 screen

- Layout: View areas (`/views/$viewId/results`, `/cleanup`) render
  `PageHeader level={2}` inside the T3 workspace layout, which owns the h1.
  Storage, Plans and Transfer pages are top-level detail/table pages with an h1.
- Review → apply (HLD §6): plan → explicit Review (exact list, what changes,
  what stays) → `ConfirmDialog` → `OperationPanel` → summary. No disk or
  catalog write happens before the confirm.
- Prototype controls are grouped in a bordered "Prototype controls" section
  labelled "Prototype: changes the simulated disk outside PlateVault". They
  stand in for the journey helpers (Siril writing output, P5 overwrite helper,
  OS Trash Put Back, transfer pause). They never write the catalog.
- Disabled controls always show their reason beside them (HLD §8).
- Spec terms keep their capitals: Result, Accepted, Complete, Keep, View,
  Target, Project, Offline, Pending, User-linked, Tool-recorded.

## State legend (applies to each component below)

D default · H hover · F focus-visible · A active · X disabled · L loading ·
E empty · R error · S selected. N/A entries carry a component-specific reason.

```
│    final image outside the View · Overwrite in place (same size and mtime) ·      │
│    Restore saved bytes                                                             │
└────────────────────────────────────────────────────────────────────────────────────┘
```

Behaviour:

- Discovery (RES-FR-01, H1): every file under the recorded output location
  (latest preparation `outputPath`, else `view.outputPath`) is classified by
  path: calibrated, registered, other intermediates, temporary/cache, logs and
  manifests, generated masters (`header.imageType` `master-*`), product
  candidates (stacks, final images) and unknown. Only product candidates and
  attached files are Result rows. A growing file reads Pending and cannot be
  accepted. No row reads Accepted until the user accepts it.
- Association vs lineage (RES-FR-03): output-location files read
  "Recorded output location"; attached files read User-linked. Lineage stays
  "Unknown lineage" unless a record says Tool-recorded. Acceptance never
  changes either value.
- Accept Result (H3, RES-FR-04): select written candidates with a kind →
  `ConfirmDialog` "Accept 3 Results": changes = record SHA-256 per product;
  show on View, Project and Target; default to Keep in cleanup. Unchanged =
  lineage values; "Acceptance does not claim that all 208 planned frames were
  used". Commit creates or updates `catalog.results`.
- Create View from results (H3a, RES-FR-05): opens the result picker (§2).
- Mark processing complete (I1, RES-FR-06/07): `ConfirmDialog`. Changes: View
  reads Complete; new membership or preparation revisions need Reopen.
  Unchanged: no file removed, cleanup does not start, accepted Results
  unchanged, "PlateVault does not infer that Siril stopped or succeeded".
  Refused (Notice refusal) while `unsettledOperationsForView` returns a
  running app-owned operation, naming it with a link. Once Complete the
  header shows a Complete badge and Clean up View (link to Cleanup).
- Notes (D09): editable while Complete; `commit` with View `expect`;
  `SaveState` saved / failed + Retry / stale + Review current revision.
- Product inputs (only for a View created from results, J26 S7/S7a): table of
  `productInputs` with originating View, kind, path and rehash state.
- Rehash (RES-AC-09): on opening Results or the picker, each accepted
  product is rehashed (simulated, ~0.6 s) against its acceptance digest. While
  running it reads "Verifying" and is not offered. Mismatch → Drifted,
  "requires review", acceptance kept as history for the earlier bytes; equal
  size and mtime do not count. Restored bytes → Unchanged, no new acceptance.

Copy:
- Empty (no output location): title "No output location yet"; body "Results
  lists what the application writes into this View's output folder. Prepare
  the View, or attach a file saved elsewhere."; action "Open Prepare".
- Empty (output folder empty): "Nothing in the output location yet" / "When
  Siril writes files into <path>, they appear here as candidates." / action
  "Attach Result".
- Refusal: "Mark processing complete refused: Prepare View is running for this
  View. Complete waits until it settles."
- Error beside Accept: "Accept Result was not saved: the catalog write failed.
  Your selection is kept; choose Retry."

## 2. Attach Result dialog and result picker (J26 S2, S4, S7, S7a)

Attach Result (H2, RES-FR-02): Dialog. Fields, each with a persistent label:
"File" (simulated OS file chooser: volumes, folders and files; offline volumes
disabled with reason), "Kind" (radio group: Final image, Linear integration,
Channel product, Mosaic panel), "Channel" (optional text, e.g. Ha), "View"
(select, default this View). Submit "Attach Result". Errors name the field:
"File: choose a file to attach.", "Kind: choose what this file is.",
"File: NGC7000-HOO.tif is already listed for this View." Result: candidate
row, User-linked, Unknown lineage.

Result picker (H3a): Dialog "Choose accepted Results". Grouped by originating
View; each row: checkbox, file, kind, path, availability, lineage, rehash
state. Not offered (checkbox disabled, reason inline): Verifying, Drifted,
Offline, Not found, Pending. Footer: "Create View from 2 Results" →
`/views/new?from=results&resultIds=…`; secondary "Add to an existing View"
(select + button) → `/views/new?viewId=…&resultIds=…`. Empty: "No accepted
Results to reuse" / "Accept Results in a View first." / action "Close".

States: D/H/F/A from primitives; X rows with reason; L "Verifying" badge; E as
above; R inline field errors; S checked rows.

## 3. Clean up View — `/views/$viewId/cleanup` (J27 S4-S11)

```
┌ Clean up View ───────────────────────────────────────── [Review cleanup] ┐
│ Choose files to send to the OS Trash. Originals outside this View and     │
│ accepted Results stay protected.                                          │
│ Trash support: Work (Astro-T7) supported · Scratch unsupported            │
│ [x] Calibrated intermediates   208 files  21.7 GB  Send to OS Trash  ▸Inspect│
│ [x] Registered intermediates   208 files  21.7 GB  Send to OS Trash  ▸Inspect│
│ [x] Other intermediates          2 files   4 KB    Send to OS Trash  ▸Inspect│
│ [x] Temporary files and caches   3 files            Send to OS Trash  ▸Inspect│
│ [ ] Prepared inputs            208 entries  0 B reclaim guaranteed    ▸Inspect│
│ [ ] Verified duplicates          1 file   58.7 MB                     ▸Inspect│
│ [ ] Logs and manifests           2 files                               ▸Inspect│
│ [ ] Unaccepted result candidates                                       ▸Inspect│
│ [ ] Unknown files                1 file                                 ▸Inspect│
│ ── Keep (protected) ── accepted Ha/OIII stacks, master_flat_Ha.fit    ▸Inspect│
│   Inspect table: file · role · other references · retained original · bytes │
└───────────────────────────────────────────────────────────────────────────┘
Review step: exact "Send to OS Trash" list and "Keep" list, per-location Trash
support with movable/blocked counts, blocked items with reasons, protected
items named with dependent Views → [Send 625 files to Trash] (ConfirmDialog).
Run: OperationPanel per-item outcomes → summary "Partial: 624 sent to Trash,
1 refused". Last cleanup record: removed / remaining lists, Keep files,
Reveal location, "Restoring relies on the OS Trash; PlateVault cannot restore
files after the Trash is emptied." Prototype controls: Put back from Trash.
```

Rules: STO-FR-01..05, STO-FR-10, STO-AC-01..04, 08, 09, 11.
- Preselected: calibrated, registered, other intermediates, temporary/cache.
  Unselected: prepared inputs, verified duplicates, logs/manifests
  (`platevault-handoff.txt`), unaccepted candidates, unknown files.
- Keep: accepted Results, drifted accepted products, generated master
  sources; selecting one is a separate explicit choice and the review names
  the product, its Project/Target and dependent Views (`productInputs`).
- Original captures outside the View folder never appear. Direct-source
  Views have no prepared entries; only processing outputs are listed.
- Retained-original proof per entry: symlink = "Link holds no image bytes;
  its target is not followed"; hardlink/copy = a byte-identical registered copy
  outside the View exists now (named) → verified; none → "Insufficient
  retained-original proof: this entry may hold the last copy" (blocked);
  copy on an offline volume → "Original on Cold-1 is offline" (blocked).
  Duplicates name the verified copy kept.
- Link sizes are shown as "0 B (link)"; hardlinks "shares bytes with the
  original; reclaim not guaranteed".
- Before Complete only "Replaced preparation entries" is eligible; other
  groups are disabled with "Available after Mark processing complete".
- Trash unsupported (Scratch): items are refused at execution, never deleted;
  summary offers Keep files and Reveal location; no permanent-delete action
  exists anywhere.
- Execution re-checks identity (sha256 + inode), proof, Trash support and
  write permission per item; changed items are blocked "Changed since review".

Copy:
- Empty (no View folder): "Nothing to clean up" / "This View has no prepared
  folder or output yet." / action "Open Prepare".
- Confirm: title "Send 625 files to the OS Trash?"; changes "Move 625 files
  from Work to the OS Trash", "Trash 208 link entries without following their
  targets"; unchanged "Original captures, accepted Results and masters stay",
  "The View stays Complete; membership does not change", "No file is deleted
  permanently". Button "Send 625 files to Trash".

## 4. Storage — `/storage` (STO-FR-11, STO-AC-12, J28 S1 entry)

Header actions: "File into library", "Archive sessions" (primary, last).
Sections, each separate (candidate display never authorizes removal):
1. Locations: name, role, path, volume and identity, availability, Trash
   support, free space; Offline rows: "Locate or remap" →
   `/settings/locations?locationId=`.
2. View footprints: View, status, View folder, entries and mode, footprint,
   output bytes, actions "Clean up View" → `/views/$id/cleanup`, "Archive
   sessions" → `/storage/archive?viewId=`.
3. Duplicate candidates: assets with more than one present copy (content
   identity), with each copy's location and path. Note: "Shown for review
   only. Removing duplicates is not part of Storage."
4. Transfers: archive and filing operations with status and phase counts →
   `/storage/transfers/$id`.
Empty copy: "No locations registered" → "Add a location" (Settings);
"No prepared Views yet" → "Open Views"; "No duplicate candidates" → "Open
Sessions"; "No transfers yet" → "Archive sessions".

## 5. Archive — `/storage/archive` (J28 S1-S5)

Plan sections: Sessions (checkbox table; offline sessions not selectable,
reason "Cold-1 is offline"); Destination (Choose destination → FolderPicker;
path, volume name and identity, "Matches the volume chosen for this plan" or
conflict, free space, writable, registered location); Planned operations
(source → destination, bytes, source SHA-256; first 8 + Show all); Affected
Views and references (current mode, "A hardlink cannot be rebuilt across
volumes", radio: "Symlink to the archived file" / "Keep the local copy
(bytes stay on Astro-T7)", no default); Fixed by this plan (membership,
exclusions, View status with live numbers). Blockers list. "Review transfer"
is disabled with the blocker list beside it.

Review: exact operations, reference effects, expected reclaim, then "Approve
transfer" → ConfirmDialog → operation → navigate to Transfer. Opening Review
freezes each source SHA-256; approval runs against those digests, so a source
changed after review shows "Source changed since review: this item will be
blocked and its source kept" and is blocked, never re-planned (J30 S4).
Conflict copy (S2): "Different volume at /Volumes/Archive: identity A7C4-9999
does not match A7C4-0001 chosen for this plan. Approval is blocked. Mount the
intended Archive, or choose a destination again."
Prototype control: "Hold one item before source retirement" (J28 P5).

## 6. File into library — `/storage/filing?sessionIds=` (J30 S1-S4, S6)

Sessions (from `sessionIds`, remove/add), destination (FolderPicker; must be a
location that accepts reviewed filing), layout preview `<destination>/<Target>/
<night>/<channel>/<original basename>`, counts per session, collisions,
footprint (same-volume move = no extra space), affected View references,
"These 83 files are already indexed; filing moves them and does not re-index".
"Review filing" re-reads the destination; a collision blocks: "Blocked:
/Volumes/Astro-T7/Library/NGC 7000/2026-09-26/OIII/Light_Cygnus_300s_OIII_0001.fits
already exists. Nothing is overwritten. Choose another destination or remove
26 Sep from this plan." Approve → ConfirmDialog → operation → Transfer.

## 7. Transfer — `/storage/transfers/$operationId` (J28 S5-S9a, J30 S4-S6)

Header: title, status, eyebrow "Storage · Archive transfer" or "Filing".
OperationPanel (Pause, Resume, Retry for Interrupted, Cancel). Phase counts:
Destination verified · Reference updated · Source retired · Source retained ·
Pending · Blocked · Uncertain. Reclaim: expected vs observed. Items table:
file, phase, status, source, destination, references (completed / blocked /
uncertain), actions "Review evidence" (dialog: snapshot SHA-256, current
source SHA-256, destination SHA-256, references, "Retry with current
evidence") and "Retry item" for blocked items. Affected Views: live
membership totals and status, "Membership and exclusions unchanged".
Interrupted copy: "Archive disconnected during the transfer. 37 items keep a
verified destination; 177 sources are retained. Retry revalidates the
volume identity and each item before resuming."
Drift copy: "Blocked: source changed after its snapshot was copied and
verified. Both versions are kept: the source keeps its new bytes and
/Volumes/Archive/NGC7000/… keeps the verified snapshot."
Prototype controls when an item is held, or blocked by source drift: "Overwrite
source (same size and mtime)", "Restore saved bytes", then Resume or Retry.
Empty: "Transfer not found" → "Open Storage".

## 8. Plan — `/targets/$targetId/plan` (J29 S1-S10; B3, K)

Sections: Planning site (select of saved sites, no automatic choice; "Manage
sites" → `/settings/sites?return=…`); Criteria (fieldset: minimum altitude,
darkness Astronomical/Nautical, maximum Moon illumination, minimum Moon
separation, minimum duration; SaveState); Windows (next 14 nights; each:
date, start-end in the site's zone, duration, max altitude, Moon; caption
"Times in Europe/Amsterdam (CEST) for Backyard"; "Prototype calculation:
astronomical suitability only. No weather, equipment or processing
readiness."); Coverage and Project checklist gaps beside it; Planned (Switch
"Planned"); Reminders (reminder site = default site, criteria, lead time
select with no default, Enable notifications; no default site → Notice
"Set a default site first. Reminders use the default site only." + "Set
default site" link; denied → refusal Notice with "Settings" and "Retry";
enabled → "Notifications on for Backyard"); Export calendar (Dialog: site,
time zone, date range, window checkboxes, file name, "Save .ics file";
"Prototype: the file downloads through the browser; the desktop app uses the
native save dialog").
Empty: no sites → "No observing sites saved" → "Add a site"; Target without
coordinates → "Position unknown" → "Open Target"; no window → "No window meets
these criteria in the next 14 nights" → "Reset criteria".

## 9. Plans — `/plans` (J29 overview)

Reminders status (on/off, site, lead time, permission, "Delivered only while
PlateVault is open. App-closed delivery is unavailable: no tested scheduler
is installed."), Turn off notifications; Planned Targets table with next
window at the reminder site; Delivered reminders (target/site/window
identity); Calendar exports (snapshot, windows, Download again: byte-identical
regeneration from the saved snapshot). Empty: "No planned Targets" → "Open
Targets".

## 10. Shell contribution

- Overlay: reminder scheduler (runs only while reminders are enabled and
  permission is granted; delivers once per target/site/window identity inside
  the lead time; records it durably; restarts suppress repeats) and the
  simulated OS notification stack (`popover="manual"`, explicit Close,
  labelled "Simulated OS notification").
- Palette: "Plan NGC 7000", "Clean up View <name>", "Archive sessions",
  "File into library".
