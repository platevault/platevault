# T4 wireframes: calibration inputs and application handoff

Track T4. Specs 068 (CAL) and 069 (PREP); journeys J23 and J24, plus the J26
adoption steps S8-S9 that land on `/calibration/$calibrationId`. Binding
context: `design/HIGH-LEVEL-DESIGN.md` (routes §4, seams §5, layouts §6, tokens
§7, components §8, states §9, copy §10). Everything below is fixture data.

T4 owns `src/features/t4/**`, `src/store/slices/t4.ts` and this file.

## 1. Model the screens share

### Calibration requirement rows (D13, CAL-FR-01 to CAL-FR-08)

Each light session in the View's membership (`view.draft`, else the latest
revision) needs three inputs: a **dark**, a **flat** and a **bias**. One row
is one (light session, kind) pair. Rows are grouped by camera, dimensions,
binning, gain/offset, channel and optical train, which is the D13 matching
geometry.

Candidates for a row are adopted masters and raw calibration sets
(calibration-type sessions) of that kind. Generated masters that were never
adopted are not candidates anywhere (CAL-AC-04).

| Criterion | Compared for | Light value | Calibration value | Result |
|---|---|---|---|---|
| Camera | all | session camera | master or set camera | equal: Compatible; different: Incompatible; missing: Unknown |
| Dimensions | all | first frame NAXIS1×NAXIS2 | master or set | as above |
| Binning | all | session | master or set | as above |
| Gain, Offset | all | session | master or set | as above; missing: Unknown |
| Image type | all | Light | recorded IMAGETYP | the recorded type must be the requested kind |
| Exposure | dark | session | master or set | equal: Compatible, else Incompatible |
| Channel | flat | session filter | flat filter | as above; missing: Unknown |
| Optical train | flat | confirmed or associated train | flat train evidence | equal: Compatible; different: Incompatible; no evidence on either side: Unknown |

Temperature is shown under **Shown, not compared**, next to both recorded
values: no temperature tolerance is set, so it never decides a match (D13,
J23 S2 negative).

Suggestion order: every criterion compatible, then masters before raw sets,
then the nearest night. Night only orders; it is never a criterion (HLD §14,
"24 Sep flats"). A row with no fully compatible candidate is **Unresolved**,
and its closest candidate is named but not preselected. Choosing a
non-compatible input without a reason (J23 S5: the 26 Sep set instead of the
30 Sep suggestion) stores it as **Unresolved**: recorded, blocking, never
handed off, until an exception with a reason (S6) or another input. Accepting
or excepting an input records its D19 basis in the T4 slice: the View revision
and each file's SHA-256 (CAL-FR-08). An input whose bytes no longer match
(an adopted master against its adoption digest, a raw set against its indexed
digest, or either against its acceptance basis) reads **Drifted**, blocks, and
is neither suggested, offered nor acceptable until the bytes return
(CAL-AC-10). A decided row also offers a master adopted after its decision as
a separate **Suggested** replacement; the decision stands until accepted
(J26 S9).

Row state is derived: a stored assignment (`view.calibration`) wins, else
Suggested when a compatible candidate exists, else Unresolved.

| State | Badge | Meaning | Handoff |
|---|---|---|---|
| Suggested | `assignment:suggested` | Preselected, not accepted | Blocks Prepare (CAL-AC-06) |
| Accepted | `assignment:accepted` | User accepted; criteria snapshot stored | Handed off |
| Exception | `assignment:exception` | Input with a non-compatible criterion, accepted with a reason for this View only | Handed off; review lists criterion and reason |
| Excluded | `assignment:excluded` | "Hand off without a flat": explicit decision that this kind is not handed off | Nothing handed off for that kind |
| Deferred | `assignment:deferred` | Decide later | Blocks Prepare |
| Unresolved | `assignment:unresolved` | No compatible input | Blocks Prepare |

### Preparation plan (PREP-FR-03 to PREP-FR-08)

Plan choices live in the T4 slice per View and persist across reloads:
input mode, link type, View folder name, output override, metadata decisions,
the revision whose membership was confirmed. `view.locationParent`,
`view.outputPath` and `settings.lastViewParent` are committed when the user
chooses a location. Nothing touches the disk before **Prepare View** is
confirmed.

Mode rules, evaluated live against the profile and the simulated disk:

| Mode | Semantics shown | Refused when |
|---|---|---|
| Linked View (suggested for verified read-only profiles) | References, not isolated backups. Symlink by default; hardlink needs an explicit confirmation naming same-volume, permission and filesystem checks and that a writing application alters the source | profile input-write behaviour unknown or write-prone (D04); destination volume cannot link; hardlink: any source on another volume |
| Direct source | Exact original paths through the profile's file list; no links, no copies | input-write unknown or write-prone; profile consumes whole folders and a source folder holds excluded or non-member frames (PREP-AC-04) |
| Copy | Isolated full copies; footprint = source bytes | free space below the footprint |
| Clone | Isolated copy-on-write clones; near-zero footprint until either side changes | destination volume has no clone support or a source is on another volume |

Refused modes stay visible, disabled, with the reason beside them (never a
silent disabled control).

## 2. Screens

### 2.1 `/views/$viewId/calibration` — Calibration for this View (E1, E2)

Rendered inside the T3 workspace (T3 owns the h1); the area title is h2.

```
┌ Calibration for this View ─────────────────────────────── [Review preparation →] ┐
│ Suggestions are never handed off until you accept them.                             │
│ [3 Accepted] [10 Suggested] [2 Unresolved]          [Accept 10 suggestions]        │
├────────────────────────────────────────────────────────────────────────────────────┤
│ ⓘ Membership: revision 2 · 208 lights · 5 sessions                                 │
│                                                                                    │
│ Ha · RedCat 51 / ASI2600MM Pro · 6248×4176 · bin 1 · gain 100 / offset 50          │
│ ☐ │ Light session      │ Kind │ Input                         │ Match       │ State │
│ ☑ │ 18 Sep · 55 frames │ Dark │ MasterDark_300s_G100…  master │ 7 compatible│Suggested│ [Why this match] [Change ▾]
│ ☑ │ 18 Sep · 55 frames │ Flat │ Flat_Ha 18 Sep · 30 frames raw│ 8 compatible│Suggested│ …
│ ... OIII · RedCat 51 group ...                                                     │
│   │ 24 Sep · 20 frames │ Flat │ Flat_OIII 30 Sep · raw         │ 8 compatible│Suggested│
└────────────────────────────────────────────────────────────────────────────────────┘
```

- Selection: suggested rows start checked, so **Accept N suggestions**
  accepts exactly the checked ones; unchecking 24 Sep's flat leaves it Suggested
  (J23 S3). Rows with nothing to accept keep the shared table's disabled
  checkbox, named for why ("accepted, nothing to accept"); a row with a
  replacement suggestion is selectable.
- The session cell shows the night and frame count only (channel and settings
  are in the group heading), the **Why this match** column is the match summary
  as a link ("All 8 criteria compatible", "Optical train unknown"), and **Change** is an icon
  menu with a full accessible name, so every row action fits the 750 px table
  frame at 1024 (critique T4-03/F1). With no suggestion left, Accept is hidden
  and Review preparation becomes the primary action (T4-04).
- **Why this match** opens a side sheet: input identity and path; Compatible,
  Incompatible and Unknown criteria in three lists; Shown, not compared
  (temperature); raw-set note "Handed to the application, which builds its
  own master. PlateVault writes no master file." (J23 S4); the exception and
  its reason when present; actions Accept, Choose another input, Record
  exception, Defer, Hand off without a flat/dark/bias. It stays available on
  accepted rows (CAL-FR-03).
- **Change** menu: Choose another input… (dialog listing every candidate with
  its match summary; a fully compatible choice is accepted, any other needs a
  reason and becomes an Exception), Record exception…, Defer, Hand off without a
  <kind>, Clear decision (back to the suggestion), Remove session from View
  (link to `/views/<id>/sessions`).
- Exception dialog: required **Reason** textarea (error "Enter a reason for
  this exception. It is kept with the unknown criterion."), lists the
  non-compatible criteria, says "Applies to this View only. The flat set's
  evidence is not changed."
- Prototype note on the sheet: none (no simulated capability here).

States: default; hover/active/focus-visible from primitives; selected
(checked rows, `bg-primary/8`); disabled (Accept with no checked
suggestion, with reason); empty — no sessions in membership: "This View has no
light sessions yet" + **Select sessions** (link to the Sessions area); error —
failed catalog write: `ActionError` beside Accept with Retry, rows keep their
state; stale — "Changed elsewhere" with Review current revision; loading N/A:
matching is synchronous over the fixture catalog.

Journey steps: J23 S1, S2, S3, S4, S6 (exception), S7 (another View: no
exception), J26 S8 negative (candidate never preselected), J26 S9 (adopted
master offered as a compatible input).

### 2.2 `/views/$viewId/prepare` — Prepare and open (E3, E4, F1-F6)

One scrolling area, sections in task order; **Review preparation** is the
last step of the plan and opens the review in place.

1. **Before you prepare** (readiness): membership saved? (draft → "Save View
   first: Review preparation uses a saved revision." + link to Sessions),
   calibration resolved? (lists Suggested, Deferred and Unresolved rows by
   session and kind with **Resolve in Calibration**), View Complete? (refused,
   "Reopen the View to prepare a new revision").
2. **Application**: radio cards PixInsight / WBPP, Siril, SETI Astro Suite Pro,
   Open in…; each card shows Verified profile or Not verified. Detail of the
   chosen profile: capability evidence (fixture text), input-write behaviour,
   supported input modes, Direct-source handoff (file list or whole folder),
   product inputs, corrected metadata via configuration; unsupported items are
   named ("Not supported: reading corrected values through configuration").
   Executable: Not configured → **Locate Siril…** (simulated chooser dialog
   with the path field); Found, Missing, Launch fails with the path. Open in…
   needs an executable and launch arguments and reads "Not a verified
   preparation profile".
3. **Corrected metadata** (E4): one row per session and field where the
   catalog value differs from what the application reads: "28 Sep · Ha · 56
   frames — Focal length: catalog 250 mm (confirmed optical train) · Siril
   reads: absent (FOCALLEN missing)". Choice (radio): Use application
   configuration (disabled when unsupported, reason named), Isolated patched
   copies (needs Copy or Clone; offers **Switch to Copy** which is an explicit
   change), Accept the source-header value, Exclude these inputs. The row
   names the effective handoff value and the materialization mode
   (J23 S10, S11; PREP-AC-06).
4. **Input mode** (F1): radio cards Linked View · Direct source · Copy · Clone
   with semantics, storage footprint, link type; refused modes disabled with
   the reason. Linked shows link type symlink/hardlink; switching to hardlink
   opens a ConfirmDialog with the limitations (J24 S3).
5. **Locations** (F2, F3): View folder parent (Not set on first use) with
   **Choose location…** (FolderPicker) and a **Folder name** field (suggested
   unique name, e.g. `NGC7000-HOO-Siril`). Live checks below: parent offline
   ("Scratch is offline. Choose another location; PlateVault never picks
   another drive."), folder exists ("…/NGC7000-HOO-Siril already exists with 1
   unrelated item (keep.txt). Choose another name or location. Nothing in it
   was changed."), write permission, links unsupported at the destination.
   Output: default `<View folder>/output/`; **Change output location…** picks a
   parent and the View folder name is appended; **Use default** resets.
6. **Review preparation** (F4): button disabled with the reason while
   readiness fails. The review lists: selection (revision, lights, sessions,
   by channel, excluded count), saved selection criteria (apart from browsing
   filters, which are never saved), profile, source references (per session
   with location and availability), calibration choices and exceptions with
   reasons, metadata decisions, View and output paths, mode and link type,
   operation count, footprint and free space, and checks (Source presence,
   Destination, Permissions, Hardlink eligibility, Free space) each Checked or
   Blocked with the reason. A subset that cannot use the mode is listed with
   paths and footprint. **Confirm membership** checkbox: "I confirm these 208
   frames and the saved selection criteria." **Prepare View** opens a
   ConfirmDialog naming what is created and what stays unchanged.
7. **Preparation** (F5, F6): once the current revision is Prepared, Before you
   prepare is hidden, Review preparation steps back to a secondary button,
   **Open in Siril** is the one filled action and sits above the per-entry
   outcome, and Application, Corrected metadata, Input mode and Locations fold
   into **Change preparation settings** (critique T4-02). Locations shows
   "Prepared here for revision N" (not a collision) with an optional unique
   name for a new preparation (critique T4-01).
   `OperationPanel` while running (Pause, Cancel);
   settled summary "Prepared: 208 of 208", "Partial: 53 prepared, 3 blocked"
   with each blocked entry and path; Retry (journaled blocked entries only),
   Review preparation again, Keep the partial View. After Prepared: **Open in
   Siril**, **Reveal View** (simulated Finder listing), Preparation details.
   Missing executable: Notice with **Choose application…** and **Reveal
   View**; the View stays Prepared. Open first re-verifies every prepared
   entry against its preparation snapshot (PREP-FR-10, PREP-AC-15): a changed
   source or entry refuses the launch, names each changed path, records no
   launch and shows **Unverified** (T4 slice) until the snapshot bytes return
   (re-checked on every disk change) or a later Open re-verifies; a preparation
   without a run journal is checked against catalog digests, else fails closed;
   PlateVault writes nothing to the frame or its entry (J24 S10a). Launch
   records "Opened (prototype: simulated launch)"; quitting never marks
   Complete.
8. **Earlier preparations**: older revisions stay listed with their state and
   path; removing their entries goes through **Clean up View** (T5).
9. **Prototype controls** (collapsible, labelled): pause after the next source
   snapshot (J24 P7), deny or restore read access for three source frames of
   this View (J24 S15), overwrite or restore a paused item's source, overwrite
   or restore one prepared 26 Sep frame in place (J24 P8), move the
   application out of its path or restore it, make the next launch fail.

States: empty (no profile chosen: "Choose an application to see its
capabilities"), loading (operation running: `OperationPanel`; no skeleton,
reads are synchronous), error (failed write beside the control; Failed
outcome), refusal (Notice refusal for collisions, unavailable parent, refused
modes), partial, paused, canceled, interrupted (after reload, Retry resumes the
recorded items), disabled (Review and Prepare with reasons), selected (radio
cards checked, `aria-checked`), focus-visible and hover from primitives.

Journey steps: J23 S5 (unresolved in review), S8, S9, S10, S11; J24 S1-S16.

### 2.3 `/calibration` — Calibration library (CAL-FR-01, CAL-FR-06)

List + detail (`ListDetail`). The list groups by camera · dimensions ·
binning · gain/offset, then kind and channel. Each item: name, kind, channel,
source (Master, Raw set, Candidate), frame count or "Master", state badge.
Candidates sit in their own group **Detected in output locations** with
"Not reusable until added" and **Add to calibration library**. A toolbar
button **Check output locations** re-runs detection and announces "No new
candidates" or "1 new candidate".

Empty: "No calibration frames indexed yet" + **Add a calibration location**
(link to `/settings/locations`). Calibration location denied: Notice warning
naming the folder with **Open Locations**.

### 2.4 `/calibration/$calibrationId` — Master or raw set

`PageHeader` (eyebrow Calibration), sections: Evidence (`KeyValueList` with the
header keyword as source), Origin and provenance (library file, or generated
in View X at path; adoption destination, verified SHA-256, adopted at), Usage
(Views with assignments and their state; `?viewId=` highlights that View),
Custody ("Protected by default during cleanup").

Adoption (candidates only, CAL-FR-06, CAL-FR-07, D05):

1. **Add to calibration library** opens the adoption review in place:
   destination folder (FolderPicker, must be inside a Calibration location),
   file name (defaults to the source name), reviewed identity and SHA-256 of
   the candidate, destination checks (exists → refusal naming the file; not in
   a Calibration location; offline; write permission).
2. **Adopt master** → ConfirmDialog → operation `adopt-master` with phases:
   Check destination again, Copy (hash bytes read vs reviewed digest), Verify
   copy (re-read), Revalidate source, Register. Outcomes: Adopted; Refused
   (destination exists, nothing written); Blocked (source drift, "a new review
   is required", any copy named unregistered); Failed (verification mismatch,
   candidate kept, copy named unregistered).
3. Prototype controls: create an unrelated file at the destination, overwrite
   or restore the candidate's bytes, pause after verification before
   registration (J26 P6), fail the next hash verification (foundation fault).

### 2.5 `/settings/applications` — Applications (PREP-FR-01, PREP-FR-02)

Settings section (h2). One card per profile: name, Verified profile / Not
verified, evidence text, capability table, executable path and state with
**Locate…** / **Change…** / **Check again**, launch arguments field for Open
in…, Back to the task when `?return=` is set. Prototype controls per profile:
move the application out of its path or restore it, make the next launch
fail.

## 4. Shared needs and local workarounds

- STATUS has no profile, executable or check values. T4 renders those with a
  T4-local `CheckBadge`/`ProfileBadge` built from the shared `Badge` and
  `TONE_CLASS` (same shape, icon + label), and reports the request.
- Fault controls the foundation does not provide (pause Prepare after a
  snapshot, pause adoption before registration, application presence) are T4
  slice state, shown only in labelled Prototype controls.
