# T2 wireframes: library home, sessions, corrections, quality, Targets and Projects

Owner: track T2. Scope: specs 064 (library inventory) and 065 (Project goals), journeys
J19 (index captures in place) and J20 (Target and optional Project). Binding inputs:
`design/HIGH-LEVEL-DESIGN.md` (IA §2, routes §4, seams §5, layout §6, tokens §7,
components §8, states §9, copy §10). Every number below is fixture data.

T2 owns `src/features/t2/**`, `src/store/slices/t2.ts` and this file. Everything else is
foundation-owned and read through its public contract. Durable edits go through
`commit()`, with `expect` on the Session, Target or Project revision. A success records an
Activity `saved` event. A failed or stale write keeps the edit on screen in `SaveState`.

## Shared T2 building blocks

| Block | Where | Content and states |
|---|---|---|
| Library scope strip | Targets, Sessions, Target | One line naming the locations the totals cover, for example "Totals cover 4 locations · 1 provisional · 1 offline", followed by a "Show scope" disclosure. Each location row shows its role, Complete, Incomplete or Provisional scope, Offline or Access denied, last indexed time, and its actions: **Rescan** (`startIndexing`), **Retry** for denied or incomplete scope, and **Choose folder again** or **Locate or remap**, which go to `/settings/locations?locationId=`. Lights show Captures and Archive locations; Calibration shows Calibration locations. |
| Indexing notice | Targets, Sessions | Shown while an `index` operation is running. Info Notice "Indexing in progress. Totals are provisional." It names each location as read, reading or queued, and links to **View progress** at `/activity` (LIB-FR-03, J19 S6). |
| Session label | everywhere | `18 Sep · Ha · 300 s`. The camera is added when two sessions would read the same: `21 Sep · Ha · 120 s · ZWO ASI533MC Pro`. |
| Copies | Sessions, Inspect session | A logical frame is counted once. Sessions with byte-identical copies in several locations read "2 copies of 48 frames" and name every location (LIB-AC-15, D16). |
| Verification pending | Sessions, Inspect session, Target | `StatusBadge quality:verification-pending` while a rescan rehash is outstanding. Pending frames leave applicable Usable totals (foundation derive). |

## 1. Targets `/targets` (home; J20 S1; LIB-FR-08, LIB-FR-10, LIB-FR-13, LIB-AC-09)

```

│ What your library holds for each sky subject. Search works offline. │
├──────────────────────────────────────────────────────────────────────┤
│ Totals cover 4 locations · 1 offline        [Show scope ▾]           │
│ ⚠ 1 session has no Target yet. [Review in Sessions]                  │
│ [🔍 Search Targets…  ] [Show: All Targets ▾]   3 matching Targets    │
│ ┌ Target ──────┬ Channels ────────┬ Captured┬ Usable┬ Unreviewed┬ … ┐│
│ │ NGC 7000     │ Ha · OIII        │ 17h 55m │ 0h 00m│ 15h 55m   │   ││
│ │  North Amer… │ ⚠ 1 needs review │         │       │ Offline 2h│   ││
│ └──────────────┴──────────────────┴─────────┴───────┴───────────┴───┘│
```

- Columns: Target (row header and link; aliases muted below), Channels (with "1 session
  needs review" in warning text below when sessions need review), Captured (with "2h 00m
  unavailable" below when non-zero), Usable, Unreviewed, Projects, Plan (`Planned` from
  `catalog.plans`). A coordinate search adds Distance after Target. Every column fits the
  750 px table frame at 1024 without horizontal scroll.
- Search matches the name and aliases, ignoring case and punctuation. Two numbers are read
  as RA and Dec in degrees (`314.7 44.5`), and the results then show the separation, for
  example "0.1° away", sorted nearest first (LIB-FR-13). Search never uses the network.
- Show: All Targets · With captures · Planned · Needs review.
- **Add Target** opens a dialog with a local record: Name (required), Aliases
  (comma-separated), RA and Dec in degrees (optional, both or neither), and Notes. Errors
  name the field: "Enter a Target name.", "Enter both RA and Dec, or neither.", "RA must be
  between 0 and 360 degrees.", "A Target named NGC 7000 already exists." Saving creates a
  record with `coordinateSource: user`, or `unknown` without coordinates.

| State | Rendering |
|---|---|
| default | Table sorted by captured integration, descending |
| hover / active | Row `hover:bg-muted/60`; the link presses |
| focus-visible | 2 px ring on the row link and sort buttons; ↑/↓ move between rows (DataTable) |
| disabled | N/A: no control on this page is ever unavailable |
| loading | `TableSkeleton` while indexing runs and no Target is known yet |
| empty, first run | "No Targets yet". Targets appear when indexed sessions carry pointing or OBJECT evidence, or when you add one. Action **Add Target** |
| empty, filtered | "No Target matches “xyz”". Action **Clear search** |
| error | Add Target: field errors beside each field; a failed commit shows ActionError with Retry inside the dialog |
| selected | N/A: the home has no selection; a Target opens its page |

- Coverage uses `targetCoverage`. Usable comes only from library-scope decisions. Sessions
  that need review are listed separately and never counted. An offline contribution counts
  in captured integration and is labelled with its last observation and "Not available as
  input".
- Contributing sessions show availability as a separate column: Available, or Offline with
  the last observed date.
- **Look up online** (LIB-AC-12, D18) runs a simulated resolver at the provider set in
  `settings.targetLookup`. Loading reads "Looking up NGC 7000 at CDS Sesame…" with a
  spinner. Success opens **Review enrichment**: coordinates (current source versus
  resolver), the aliases it would add, the object type, and the provider with its fetch
  time. The dialog states "Capture metadata stays as observed: OBJECT labels and pointing
  evidence do not change." Its action is **Accept enrichment**. A failure shows the warning
  Notice "Lookup failed: CDS Sesame did not respond. NGC 7000 and its sessions stay usable."
  with **Retry**. When lookup is off, the button is disabled with the reason "Online lookup
  is off in Settings › Target lookup", linked to `/settings/targets?return=`.
- **Edit record**: name, aliases, RA/Dec and notes, committed with `expect` on the Target
  revision. A stale write shows "Changed elsewhere" and **Review current revision**.
- Actions: **Plan** goes to `/targets/$id/plan` (T5), **New Project** to
  `/projects/new?targetId=`, and **Create View** to `/views/new?from=target&targetId=`
  (T3).

States: default · hover/active on links and buttons · focus-visible ring · disabled (Look up
online when lookup is off, with its reason) · loading (lookup) · empty (no contributing
session: "No session is associated with NGC 7000 yet." with **Review sessions**) · error
(lookup failure, write failure) · selected N/A (no selection; the record is the subject).
Unknown Target id: EmptyState "This Target does not exist" with **Go to Targets**.

## 4. Inspect session `/sessions/$sessionId` (J19 S9-S13, S15; LIB-FR-05, -09, -11, -12; LIB-AC-06, -08, -10, -14)

```

26 Sep · OIII · 300 s  [Incomplete scope] [Offline]      [File into library] [Create View]
(superseded / revision / offline / incomplete notices)
Capture metadata (observed)          KeyValue ×2 columns, each value with its source
Target  [Needs review]
  Observed evidence  (EvidenceList: OBJECT "Cygnus field" conflicts; pointing agrees)
  Confirmed          Not confirmed
  Target [NGC 7000 ▾]  [Confirm Target]   (SaveState)
Equipment  [Associated]
  Observed evidence  (INSTRUME, TELESCOP, FOCALLEN, optical-train record)
  Optical train [RedCat 51 / ZWO ASI2600MM Pro · Detected ▾] [Confirm equipment]  (SaveState)
  No matching record? Add one in Settings › Equipment (return here)
Catalog corrections and grouping revisions
  Corrections change the PlateVault catalog only; source headers stay as captured.
  (table: field, observed, corrected, revision, when)        [Correct filter…]
Copies (location, frames, availability, last observed)
Frames (library quality)
  [All|Unreviewed|Usable|Unusable|Changed content|Verification pending|Unavailable]
  (selection) [Mark usable] [Mark unusable] [Reset to Unreviewed]
  table: file, captured at, library quality (+ previous decision when changed), availability (+ last observed below), copies
```

- Observed evidence and the user's confirmation are separate. Confirmation adds a `user`
  evidence row and never edits the observed rows (J19 S10). The OBJECT label is shown and
  never treated as identity.
- **Confirm Target**: a Select of local Targets, prefilled with the associated value.
  Without a choice it shows "Choose a Target to confirm." (field error). It commits with
  `expect` on the session revision.
- **Confirm equipment**: a Select of optical trains, each with a Manual or Detected badge.
  Confirming promotes a Detected train to Manual (seam 3). With no train record, the
  section reads "No optical train record yet" and offers **Add an optical train**, which
  goes to `/settings/equipment?return=/sessions/<id>`.
- **Correct filter…** (D15, LIB-AC-10) opens a dialog in two steps. Edit: observed FILTER
  (read-only) and the corrected filter (a Select of catalog filters). Review: "Creates
  grouping revision 2: 55 frames move to a new 18 Sep · OIII · 300 s session (or join the
  existing one). This session stays inspectable as replaced. Frame identities, View
  membership and source headers stay unchanged. Projects linking this session link the
  new one." The action is **Apply correction**. On success the page opens the new session.
  A failure shows ActionError with Retry; a stale write is refused.
- Exposure corrections are out of scope: the shared totals read the observed EXPTIME. The
  dialog names only Filter (see Open gaps).
- Frame quality is a library-scope decision. **Mark usable**, **Mark unusable** and
  **Reset to Unreviewed** open a ConfirmDialog. This will: "Set library quality to Usable
  for 12 frames" and "Change usable totals for NGC 7000 and every Project that links this
  session". Unchanged: "Files on disk and source headers", "View membership", "Project
  rejections". The confirm label repeats the count: "Mark 12 frames usable".
- Changed content (LIB-AC-14) reads `Changed content · was Usable on 6 Sep`. Marking it
  again records a decision on the current bytes.

States: default · hover/active · focus-visible · disabled (Confirm Target while the
choice equals the confirmed value, with "Already confirmed"; frame actions with no
selection carry `aria-disabled` and "Select frames first") · loading N/A (store reads are
synchronous; no simulated async work on this page) · empty (no frame matches the quality
filter: **Show all frames**) · error (`SaveState failed` + Retry; `stale` + Review current
revision; field error) · selected (frame rows; SelectionBar). Unknown id: EmptyState "This
session does not exist" with **Go to Sessions**. A superseded session: Notice "Replaced by
grouping revision 2. It is kept for traceability and does not count in totals." with
**Open current session**; edits are hidden.

## 8. Activity `/activity` (LIB-FR-10; seam 16)

- "In progress": every running, paused or interrupted operation in an `OperationPanel`
  (Pause, Resume, Retry, Cancel by kind). When nothing is running: "Nothing is running."
- "History": ToggleGroup All · Operations · Not saved · Refused · Saved, with counts.
  Table columns: When, Outcome (StatusBadge), What (title and detail), Open. **Open**
  links to the owning surface `href`. Operation rows have **Show items**, which expands
  the OperationPanel.
- Outcome badges: an operation's settled status (`operation:*`), write-failed
  (`save:failed`, "Not saved"), write-refused (`save:stale`, "Changed elsewhere"), refusal
  (`item:blocked` labelled "Refused"), saved (`save:saved`).

States: default · hover/active · focus-visible · disabled N/A (every filter is always
available) · loading N/A · empty: "No activity yet". Indexing, saves and refusals appear
here. Action **Go to Targets**; filtered empty: "No Not saved entries" with **Show all** ·
error N/A (the log is the error surface) · selected (filter toggle `aria-pressed`;
expanded row).

## Open gaps (recorded, not stubbed)

- Exposure corrections: `sessionBreakdown` and `targetCoverage` read the observed EXPTIME,
  so a catalog exposure correction would leave the totals unchanged. T2 offers filter
  correction only. A foundation change would let derive read the corrected exposure.
- A filter correction that matches an existing session merges both into one new revision.
  If a later rescan finds a new file whose original grouping key equals a superseded
  session's id, the foundation `readFiles` reuses that id. This is a foundation edge case.
