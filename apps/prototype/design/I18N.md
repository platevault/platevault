# i18n: message catalogue and lint gate

How the prototype sources user-visible copy, and how to extract the rest. Ported from the legacy `apps/desktop` setup (spec 046, research R5; spec 061).

## The stack

| Piece | Where |
| --- | --- |
| Catalogues, en-GB source and pt-BR machine-generated | `messages/en-GB.json`, `messages/pt-BR.json` |
| inlang project: base locale, locales, message format | `project.inlang/settings.json` |
| Compiled messages (git-ignored) | `src/paraglide/`, from `pnpm i18n:compile` or the Vite plugin |
| Import surface, locale metadata (`nativeName`, decorative `flag`, `reviewStatus`) | `src/lib/i18n.ts` |
| Active locale: the saved preference, read by Paraglide's `custom-preferences` strategy | `src/app/preferences.ts` |
| Lint rules `alm/no-user-string`, `alm/no-js-plural`, `alm/require-disable-reason` | `eslint-rules/no-user-string.js`, wired in `eslint.config.js`; tests in `eslint-rules/tests/` (`pnpm test:lint-rules`) |
| Gates | `eslint.config.js` (`alm/*` at error), `scripts/check-i18n-catalog.mjs`, `scripts/check-i18n-locale-drift.mjs` |

`pnpm typecheck` and `pnpm build` compile the catalogue first. `pnpm lint` runs ESLint with `--max-warnings 0`, then `pnpm lint:i18n` (catalogue lint and locale drift).

## Using a message

- In a component: `const m = useMessages()` (from `@/app/preferences`), then `m.nav_home()`. The hook re-renders the component when the language changes; a bare `m` import does not.
- Outside React (event handlers, announcements, `refusalFrom`): `import { m } from "@/lib/i18n"`. It reads the locale at call time.
- Module-level data that carries a label (nav items, `STATUS`): make the label a getter, `get label() { return m.nav_home() }`, so every read is in the chosen language. A plain constant is evaluated once, at load.
- A helper that words an enum takes `m` from the caller: `gateWord(m, state)`, `issueCopy(m, issue)`, typed `Messages`.
- Domain objects and persisted store records never carry English. They carry a `MessageRef` (`src/lib/i18n.ts`): a catalogue key plus typed params from `msg()`, data from `verbatim()`, or punctuation-joined pieces from `joinRefs()`. The UI words it at render with `say(m, ref)`, so a language switch re-words derived and persisted copy (Activity, operations, warnings, reasons) without a reload. Enum maps (`STEP_NAME`, `GATE_WORD`, `MODE_NAME`, …) hold refs. Name helpers (`rigName`, `subjectName`, `sessionLabel`, …) take `m`, with ref twins (`rigRef`, …) for building copy.
- Never put a ref in a template literal or `.join()`: it renders "[object Object]". Word it with `say` first. `m.*()` params accept only `string | number` (the `Messages` type in `src/lib/i18n.ts`), so tsc rejects a ref passed there; `msg()` params may nest refs.
- Never import `@/paraglide/*` directly.

## Keys

Flat snake_case, `<area>_<element>_<intent>` (legacy R5): `shell_sidebar_show`, `folder_picker_empty`, `palette_group_actions`.

- Area is the surface: the foundation uses `app_`, `nav_`, `shell_`, `palette_`, `shortcuts_`, `issues_`/`issue_`, `status_`, `status_bar_`, `step_`, `settings_`, `table_`, `selection_`, `folder_picker_`, `confirm_`, `operation_`, …. A feature uses its own topic: `home_`, `sessions_`, `projects_`, `runs_`, `review_`, `targets_`, `plan_`, `calibration_`.
- One canonical key per concept. Reuse `verb_*` (Add, Cancel, Retry, …), `common_*`, `status_*` (every status word) and `nav_*` before adding a synonym. `pnpm lint:i18n` rejects two keys with the same multi-word value.
- Lift the exact current English. Rewording is a separate, visible change.

## Interpolation

`"shell_next": "Next: {label}"` → `m.shell_next({ label })`. Inputs are type-checked: a missing or extra one fails `tsc`. Use `count`, `name`, `path` where they fit.

- One message per sentence. Never build a sentence from fragments, `` `${m.a()} ${noun}s` ``: word order and agreement differ by language.
- Joining finished pieces with punctuation only is fine: `` `${text} · ${action}` ``. The rule ignores templates with no letters.
- Pass raw numbers into persisted message refs (`{ n: { count } }`, `{ size: { bytes } }`). `say()` formats `count` and `bytes` in the reader's active locale, just as it does `night`; use `formatCount` or `formatBytes` when a finished string is needed immediately.

## Plurals

An inlang variant message, never a JS ternary (`alm/no-js-plural` flags `n === 1 ? "" : "s"` and paired `_singular`/`_plural` calls):

```json
"issues_count": [
  {
    "declarations": ["input count", "local countPlural = count: plural"],
    "selectors": ["countPlural"],
    "match": {
      "countPlural=one": "{count} issue",
      "countPlural=*": "{count} issues"
    }
  }
]
```

- The catch-all is `=*`, not `=other`: pt-BR has a `many` category (1,000,000), and a message with no matching variant renders its key.
- Declare every other placeholder: `"input name"` before the `local` line.
- Each locale writes its own variants: en-GB `{count} blocked` needs none, pt-BR does (`bloqueado`/`bloqueados`).
- English-only `plural()` is gone from `src/lib/format.ts`; counts are variant messages.

## pt-BR

Every en-GB key needs a pt-BR entry in the same change: the drift gate fails on a missing or orphaned key. pt-BR is `reviewStatus: "machine-generated"` in `LOCALE_META`, so the language picker marks it. A new locale needs a `locales` entry in `project.inlang/settings.json`, a `messages/<locale>.json`, and a `LOCALE_META` entry (typecheck fails without it).

## The gate

`alm/no-user-string` and `alm/no-js-plural` are errors on all of `src/`. `alm/no-user-string` is a heuristic: it catches JSX text, user-facing attributes, toast arguments and returns from `*Label`/`*Text`/`*Title`/`*Message` helpers, but not every string a domain function returns. A pt-BR pass over the rendered routes catches the rest: switch the language and look for remaining English.

Everything a user can see is in scope, the review and dev surfaces included: the design-system page (`ds_*`), the component catalogue (`catalogue_*`), the simulation sheet (`simulation_*`) and the Prototype controls (`prototype_*`). Copy that names the prototype or the simulated world goes under `prototype_*` or `simulation_*`, the only keys `check-copy` lets say so. Seed library content that a user would have typed (Project notes, an exception reason) comes from `seed_*` keys, worded in the language active when the library is built; names stay data.

`I18N_IGNORES` holds only tests (`**/*.test.{ts,tsx}`, `**/*.spec.{ts,tsx}`) and fixtures (`**/__fixtures__/**`): their literals are assertions and samples, never rendered. `src/domain/seed.ts` is under the gate: its remaining literals are names and data (targets, volumes, rigs, paths), which the rule does not flag.

A genuinely non-user string takes `// eslint-disable-next-line alm/no-user-string -- <reason>`; an unused directive is an error, and so is a directive with no reason after ` -- ` (`alm/require-disable-reason`, every file of `src/`). Valid reasons are proper names and catalogue designations (Messier, NGC, filter, camera and volume names), file names and paths, and code identifiers (FITS keywords, component names). The directives in `src/` today:

| Where | Reason |
| --- | --- |
| `features/v5/a-home/import.tsx` (IMAGETYP, OBJECT rows) | FITS header keywords |
| `app/catalogue/feedback.tsx`, `previews.tsx` (sample blockers and runs) | target, filter and volume names |
| `app/catalogue/fields.tsx` (filter options, camera groups) | filter and camera model names |
| `app/catalogue/fields.tsx` (section description) | source file paths |
| `app/simulation-panel.tsx` (two path placeholders) | example paths |

Catalogue sections titled by the components they show use `ComponentSection` (`app/catalogue/specimen.tsx`): it takes the exported names as `components`, code identifiers that stay the same in every language, so they need no directive.

`scripts/i18n-catalog-baseline.txt` lists accepted duplicate en-GB values whose pt-BR must differ (gender or part of speech), each with its reason.

## Extraction pitfalls

- Do not find elements by their accessible name or text (`button[aria-label^="More actions"]` in the locations page); it breaks in pt-BR. Use a `data-*` hook, as the folder picker's `nav[data-volumes]` does.
- `src/lib/format.ts` formats dates and numbers with the active locale via `getLocale()`; `format.ts` owns the locale-specific month names used for product copy.
